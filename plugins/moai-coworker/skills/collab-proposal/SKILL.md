# B2B 제안서 작성

## 적용 범위

민간 고객의 영업 제안과 공공조달 입찰의 문서 초안을 지원합니다. 정부 지원사업 신청은 `moai-consultant:consult-gov-grant`, 투자자 IR은 `moai-accountant:finance-investor-relations`로 연결합니다. 실제 입찰 제출·계약 체결은 별도 실행과 권한 확인이 필요합니다.

## 입력 확인

- 고객 요구사항 또는 해당 공고·RFP의 최신 원문, 공고번호, 발주기관, 마감 시각
- 자사 제품 기능·가격·계약 조건·인증·수행 실적의 증빙
- 제출 형식, 페이지 한도, 평가 기준, 필수·선택 서류
- 고객사명과 담당자 표기, 공개 가능한 레퍼런스 범위

자료를 읽지 못하면 항목별로 `확인 필요`를 남깁니다. 사용자 제공 정보와 원문 공고, 실제 증빙을 구분합니다. 다른 고객의 과거 제안서는 재사용 권한·비밀 유지 범위를 확인합니다.

## 작성 순서

1. RFP가 있으면 요구사항을 원문 위치와 함께 목록화합니다. 공고가 없으면 고객이 밝힌 요구만 정리합니다.
2. 각 요구에 자사 근거를 연결하고 `충족 증빙 확인`, `불일치`, `미확인`으로 구분합니다. ISO·ISMS·매출·실적 등은 증빙 없이 충족 처리하지 않습니다.
3. 고객 문제, 제안 방식, 기능·운영 범위, 비용, 위험과 전제를 문서화합니다. 목차는 공고 양식을 우선하고, 자유 제안에서는 필요한 섹션만 씁니다.
4. ROI나 일정은 입력 자료와 계산 근거가 있을 때만 제시합니다. 고객의 확정 예산이나 마감은 임의 우선순위로 바꾸지 않습니다.
5. 가격에 VAT 포함 여부가 주어졌는지 확인합니다. 모르면 임의로 정하지 않고 견적 담당자 확인 항목으로 남깁니다.
6. 공공조달이면 `references/nara-jangteo.md`를 읽고, 해당 기관·공고에 실제 적용되는 자격·서류·계약 방식을 담당자와 확인합니다.
7. 최종 발송·제출 전에 사용자가 누락 항목, 실제 증빙, 가격과 문구를 검토할 수 있도록 체크리스트를 제공합니다.

## 출력 형식

```markdown
# [고객/공고] 제안서 초안

## 제안 개요
[확인된 요구와 자사 제안]

## 요구사항 대응
| 요구 | 원문 위치 | 자사 대응 | 증빙 | 상태 |
|---|---|---|---|---|
| [요구] | [페이지/항목] | [대응] | [자료] | 충족 증빙 확인/불일치/미확인 |

## 구현·운영 범위
[확인된 기능, 지원 범위, 제외 사항]

## 가격·일정
[실제 견적과 합의된 일정 또는 확인 필요]

## 위험·결정 사항
[남은 조건과 담당자 검토 항목]
```

`[추정]`은 없는 숫자를 만들어 넣는 수단이 아닙니다. 수치·시장 규모·효과를 쓸 때는 출처, 기준일, 산식을 함께 적습니다. 문서 파일이 필요하면 현재 앱이 지원하는 `moai-officer:doc-docx`·`doc-pptx`·`doc-xlsx` 등의 기능을 확인한 뒤 요청한 형식으로 제작합니다. 파일 작성과 외부 제출·발송을 구분합니다.

## 관련 스킬

- `moai-consultant:consult-market`: 실제 산업·시장 자료 조사
- `moai-lawyer:legal-contract-review`: 계약 조건 검토
- 서술형 문장은 이 스킬에서 RFP·자사 증빙·가격·일정과 대조하고 문체를 검수합니다. `moai-coworker:ai-slop-reviewer`가 노출된 경우 추가 검수하고, 별도 설치된 `moai-writer:korean-humanize`가 노출된 경우에만 윤문합니다.
- `moai-officer:doc-docx` · `moai-officer:doc-pptx` · `moai-officer:doc-xlsx`: 요청된 문서 형식 제작
