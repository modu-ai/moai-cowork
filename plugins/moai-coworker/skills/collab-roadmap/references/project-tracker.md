# 프로젝트 로드맵·마일스톤 가이드

제공된 목표와 현재 상태를 기준으로 범위, 선행 조건, 마일스톤을 정리한다.

## 입력

- 목표와 완료 기준, 현재 진행 상황
- 실제 담당자·승인권자, 예산·리소스, 외부 의존성
- 사용자가 정한 마감·우선순위와 기존 계획

## 작성 절차

1. 자료에서 확인한 작업과 새 제안을 구분한다.
2. 완료 기준이 검증 가능한 마일스톤으로 묶는다.
3. 담당자·비용·일정이 정해지지 않았으면 `미정`으로 남긴다. 유사 프로젝트의 일정을 근거 없이 복사하지 않는다.
4. 위험은 근거, 영향과 확인할 지표를 적고 확률 수치는 자료가 있을 때만 계산한다.
5. 진행률과 상태는 실제 기록에 근거해 갱신한다. 대시보드를 생성하거나 팀에 공유하지 않았다면 완료라고 말하지 않는다.

사용자가 파일을 요청하고 현재 앱에서 쓰기가 가능할 때만 합의한 위치에 저장한다. 별도 에이전트 팀이나 `_workspace/` 생성을 필수로 가정하지 않는다.
