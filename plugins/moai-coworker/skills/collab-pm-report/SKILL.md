# 팀 주간보고

## 목적

완료한 일, 진행 중인 일, 다음 계획, 위험과 의사결정 요청을 읽는 사람에게 맞게 정리합니다. 조직의 기존 양식이 있으면 그 양식을 따르고, 없으면 아래 구조를 출발점으로 사용합니다. 임원용 요약과 팀 내부판은 요청된 경우에만 따로 작성합니다.

## 입력 확인

1. 보고 기간, 팀, 대상 독자와 기존 양식을 확인합니다.
2. 사용자가 지정한 Notion·Linear·Asana·Slack 등의 연결 자료가 현재 앱에서 실제로 사용 가능한지 확인합니다. 접근 권한이 있어도 관련 범위만 조회합니다.
3. 첨부 파일이나 자유 텍스트만 있다면 그 내용으로 작성합니다. 연결 도구가 없거나 조회에 실패하면 실패 범위와 추가로 필요한 자료를 밝힙니다.
4. 완료·진행 상태, 담당자, 수치, 목표값, 날짜의 출처와 기준일을 기록합니다. 서로 다른 서비스의 상태를 병합할 때 중복·불일치를 확인합니다.

## 보고서 구성

| 섹션 | 기록할 내용 |
|---|---|
| 핵심 지표 | 실제 지표와 측정 기간. 목표가 있을 때만 목표 대비를 계산 |
| 완료 | 확인된 결과와 산출물 링크. 효과는 측정됐을 때만 기재 |
| 진행 중 | 현재 상태, 막힌 일과 확인된 다음 단계 |
| 다음 계획 | 합의된 우선순위와 기한. 미정이면 미정으로 표시 |
| 위험·이슈 | 근거, 영향, 대응 담당자가 정해졌다면 담당자 |
| 결정 요청 | 결정권자에게 필요한 질문, 선택지와 확인할 전제 |

내용이 없는 섹션에 수치나 사건을 만들지 않습니다. 의사결정 요청이 없다면 `없음`이라고 적습니다. 사용자가 제시한 일정은 임의의 P0/P1/P2로 바꾸지 않고 목표인지 확정된 약속인지 구분합니다.

## 작성과 검토

- 업무 기록을 단순 시간순으로 복사하지 않고 결정에 필요한 결과를 앞에 둡니다.
- 수치에는 출처·기간·단위를 적습니다. `[추정]` 표시는 없는 숫자를 만들라는 허가가 아닙니다.
- 개인별 비난·평가는 업무 보고에 임의로 넣지 않습니다.
- 외부 공유 문서는 대상과 공개 범위를 확인하고, 민감 정보는 승인된 범위만 포함합니다.
- 초안 작성과 실제 전송·공유는 구분합니다. 연결 서비스를 조회하지 않았다면 자동 동기화했다고 말하지 않습니다.

## 출력 예시

```markdown
# 주간보고 — [팀명] · [보고 기간]

## 핵심 지표
- [지표, 값, 기간, 출처 또는 자료 없음]

## 완료
- [확인된 결과와 근거]

## 진행 중
- [현재 상태와 막힌 일]

## 다음 계획
- [합의된 우선순위와 일정 또는 미정]

## 위험·이슈
- [확인된 위험과 대응 또는 없음]

## 결정 요청
- [결정할 질문과 필요한 자료 또는 없음]
```

임원용 압축 요약은 `moai-coworker:collab-exec-summary`를 사용하거나 위 보고서에서 핵심 판단만 추립니다. 슬라이드가 필요하면 `moai-officer:doc-pptx`의 현재 기능을 확인합니다. 스탠드업·회고 자료도 사용자가 제공했을 때만 요약합니다.

## 관련 스킬

- `moai-coworker:collab-roadmap`: 향후 제품 방향·마일스톤 계획
- `moai-coworker:collab-exec-summary`: 경영진용 압축 요약
- `moai-coworker:ai-slop-reviewer` · `moai-writer:korean-humanize`: 서술형 문장 검토
- `moai-officer:doc-pptx`: 요청된 발표 자료 제작
