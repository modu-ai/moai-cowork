# UX 리서치

요청에 맞춰 `references/ux-research.md` 또는 `references/user-feedback-analysis.md`를 읽는다. 인터뷰를 계획하는 일과 이미 수집된 응답을 분석하는 일을 구분한다. 접근하지 못한 고객 기록이나 수행하지 않은 인터뷰를 조사 결과로 제시하지 않는다.

## 진행 방법

1. 연구 질문, 대상 사용자, 제품 단계, 사용자가 제공한 자료와 사용할 수 있는 채널을 확인한다.
2. 계획 요청에는 참여자 기준, 질문·과제, 동의와 기록 방법, 관찰할 지표를 제안한다. 모집·발송·녹음은 명시된 권한과 실제 도구가 있을 때만 진행한다.
3. 분석 요청에는 자료의 출처·기간·표본·누락·선택 편향을 적고 원문과 해석을 분리한다. 개인 식별 정보는 보고 목적에 맞게 최소화한다.
4. 페르소나는 실제 연구 자료에서 확인된 패턴으로 만들고, 자료가 없으면 검증 전 가설 페르소나로 표시한다. 개수는 데이터가 뒷받침하는 만큼만 정한다.
5. NPS나 CSAT는 질문 문항, 응답 척도, 응답 수와 집계 방식을 확인한 뒤 계산한다. 숫자 하나만 제공됐다면 산식이나 원인을 역추정하지 않는다.
6. 발견과 권고를 원자료에 연결하고, 후속 검증 방법을 제안한다. 표본의 범위를 넘어 전체 고객의 선호라고 단정하지 않는다.

## 출력

요청에 맞는 인터뷰 가이드, 사용성 테스트 계획, VOC 분류표, 설문 해석, 검증 전 페르소나 또는 연구 결과 요약을 낸다. 각 발견에는 근거 자료와 불확실성을 붙인다. 문체를 다듬을 때 인용문의 의미와 수치를 보존한다.

화면 자체의 사용성·접근성 평가는 `moai-coworker:collab-ux-design`을 사용한다.
