# 영업 플레이북

특정 고객사나 고객군을 상대로 반복해서 쓸 수 있는 접근 방법을 정리한다. 사용자가 제공한 제품 설명, 가격, 고객 자료, 실제 영업 기록을 먼저 확인한다. 외부 자료가 필요한 경우 접근 가능한 공식 공시·고객사 자료 등을 조회하고 출처와 확인일을 적는다. 조회하지 못한 사실은 확인 필요로 표시한다.

## 작성 순서

1. **범위 확인**: 판매 제품, 대상 고객군, 영업 목표, 사용 가능한 채널과 제약을 정리한다. 빠진 정보가 있어도 가능한 범위의 초안을 만들고 결정에 꼭 필요한 항목만 묻는다.
2. **고객 이해**: 확인된 고객사의 업무, 구매 절차, 관여 부서를 기록한다. 회사 규모·매출·예산·조직도·담당자의 의도를 근거 없이 채우지 않는다. 고객사가 지정되지 않았다면 고객군 가설로 표시한다.
3. **접근 전략**: 고객의 확인된 문제와 제품의 입증된 기능을 연결한다. 채널별 첫 연락 문안, 발견 질문, 다음 단계의 조건을 제시한다. 연락처 수집이나 발송은 사용자의 요청과 해당 도구의 권한 범위에서만 한다.
4. **예상 질문**: 가격, 도입 부담, 보안, 경쟁 대안 등 관련 있는 질문을 고른다. 답변은 확인된 제품 자료와 사례를 인용한다. 자료가 없으면 답을 만들어내지 않고 확인할 담당자나 자료를 적는다.
5. **측정 계획**: 실제로 기록할 수 있는 리드, 미팅, 제안, 계약 지표를 선택한다. 기준값·목표값은 제공된 데이터와 사용자 목표에서만 가져온다. 없으면 측정 방법과 기준값 수집 계획을 쓴다.
6. **검수**: 사실, 가설, 권장 행동을 구분하고 각 외부 주장에 출처를 붙인다. 경쟁사 우위, ROI, 절감액, 도입 기간, SLA, 고객 사례는 검증된 자료가 있을 때만 확정 표현으로 쓴다.

## 출력 틀

```markdown
# [제품 또는 고객군] 영업 플레이북

## 입력과 근거
- 제품·가격·고객 범위: [제공 자료]
- 확인되지 않은 정보: [확인 과제]

## 고객과 구매 맥락
- 확인된 사실: [출처]
- 검증할 가설: [질문 또는 필요한 자료]

## 접근 전략
| 채널 | 선택 이유 | 첫 메시지 | 다음 단계 |
|---|---|---|---|

## 예상 질문과 답변
| 질문 | 확인할 쟁점 | 근거 있는 답변 또는 확인 과제 |
|---|---|---|

## 측정과 개선
| 지표 | 집계 기준 | 현재값·출처 | 목표·근거 |
|---|---|---|---|

## 실행 전 확인 사항
- [ ] 대외 문안의 제품 주장과 사례 확인
- [ ] 고객사 정보와 연락 권한 확인
```

사용자가 공공 입찰을 다룬다면 실제 공고와 제안요청서의 자격·평가·제출 요건을 확인한 뒤 해당 요건에 맞춰 작성한다. 공고 없이 낙찰 가능성이나 입찰 절차를 확정하지 않는다.

문체 검수가 필요하면 `moai-coworker:ai-slop-reviewer`나 `moai-writer:korean-humanize`를 사용할 수 있다. 검수 과정에서도 숫자와 사실의 근거를 보존한다. 단일 제안서가 목적이면 `moai-coworker:collab-proposal`을 사용한다.
