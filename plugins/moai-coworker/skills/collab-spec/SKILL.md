# 제품 명세와 AI 도입 검토

요청에 따라 `references/product-manager.md` 또는 `references/ai-strategy.md`를 읽고 필요한 부분만 적용한다. 자료가 없다는 이유로 제품, 사용자, 팀 규모, 예산, 일정, 예상 성과를 만들어내지 않는다. 확인된 요구와 제안, 미결정 사항을 구분한다.

## 진행 방법

1. 사용자가 해결하려는 문제, 대상 사용자, 원하는 산출물과 제공 자료를 확인한다. 입력이 부족해도 가능한 초안을 먼저 작성하고 중요한 빈칸을 질문으로 남긴다.
2. 기존 자료와 접근 가능한 근거에서 요구사항을 뽑는다. 상충하는 요구는 어느 자료에서 왔는지 보여주고 결정이 필요한 쟁점으로 남긴다.
3. 사용자 요청 범위에 맞는 문서만 작성한다. PRD 요청에 로드맵·스프린트 계획·회고를 자동으로 붙이지 않는다.
4. 각 요구사항은 관찰 가능한 동작과 수용 기준으로 쓴다. 성능·보안·접근성 기준이 필요한 경우 해당 제품의 실제 제약과 검증 방법을 함께 적는다.
5. 우선순위는 사용자가 정한 기준으로 매긴다. RICE, MoSCoW 같은 방법은 점수나 분류 근거가 있을 때 선택적으로 쓴다.
6. 수치 목표와 일정은 사용자 입력이나 검증된 자료에 있을 때만 기입한다. 없으면 측정 방법, 기준값 수집, 결정 담당자를 제시한다.

## PRD 기본 틀

- 배경과 문제: 확인된 사용자 문제와 근거
- 목표와 측정: 지표 정의, 기준값·목표값의 출처 또는 미정 표시
- 범위: 포함·제외 기능, 사용자 흐름
- 요구사항: 식별자, 동작, 우선순위 근거, 수용 기준
- 제약과 의존성: 기술·운영·법적 검토가 필요한 항목
- 결정 대기: 확인할 질문, 담당자, 필요한 자료

AI 도입 전략 요청은 현재 업무와 데이터 접근, 적용 후보, 작은 검증 방법, 비용과 위험, 성과 측정 방식을 정리한다. 실제 데이터 없이 ROI나 성공 확률을 계산하지 않는다.

정부 일반 지원사업 신청서는 `moai-consultant:consult-gov-grant`, 학술·연구비 과제 신청서는 `moai-tutor:education-grant-writer`를 사용한다. 문체 검수가 필요하면 `moai-coworker:ai-slop-reviewer`와 `moai-writer:korean-humanize`를 선택적으로 사용하되 요구사항과 수치를 바꾸지 않는다.
