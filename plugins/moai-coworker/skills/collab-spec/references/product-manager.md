# 제품 요구사항 작성 가이드

사용자가 요청한 제품 문서의 범위만 작성한다. PRD, 로드맵, 사용자 스토리, 스프린트 계획은 서로 다른 산출물이다.

1. **문제와 근거**: 대상 사용자, 현재 불편, 이를 뒷받침하는 인터뷰·지표·기존 문서를 구분한다.
2. **범위**: 해결할 문제와 이번에 다루지 않을 항목을 명시한다. 결정되지 않은 범위는 미정으로 표시한다.
3. **기능 요구사항**: 사용자 동작과 시스템 반응을 검증 가능한 문장으로 쓰고 식별자를 붙인다. 오류·빈 상태·권한 경계도 관련 있을 때 포함한다.
4. **비기능 요구사항**: 성능, 접근성, 보안, 호환성 요구를 해당 제품의 환경과 측정 방법에 맞춰 적는다. 수치를 임의로 채우지 않는다.
5. **우선순위와 의존성**: 사용자가 제시한 가치·위험·노력 자료로 판단하고 근거가 없는 점수는 매기지 않는다.
6. **검토**: 요구사항과 수용 기준이 연결되는지, 상충·누락·미결정 사항이 무엇인지 확인한다.

팀 규모·속도·일정 정보가 없다면 스프린트 용량을 추정하지 않는다. 문서 저장 위치와 파일 분할은 사용자 요청이나 현재 작업 환경에 맞춘다. `_workspace/` 생성과 다중 에이전트 실행을 전제하지 않는다.
