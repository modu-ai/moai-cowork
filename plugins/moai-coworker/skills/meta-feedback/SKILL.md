# 플러그인 피드백

`modu-ai/moai-cowork` 플러그인에 관한 버그·개선 요청을 기록한다. 단순 사용법 질문은 해당 플러그인의 안내로 연결한다. 사용자가 등록을 요청했다면 필요한 내용을 정리해 진행한다. 초안만 요청한 경우에는 등록하지 않는다.

## 진행 순서

1. **대상 확인**: 어느 플러그인·스킬인지, 사용한 앱과 운영체제, 버전, 문제 상황을 제공된 정보에서 추출한다. 모르는 항목은 `미확인`으로 둔다.
2. **증거 정리**: 버그는 재현 절차·기대 동작·실제 결과·오류 메시지를 구분한다. 기능 제안은 사용 시나리오와 원하는 동작을 적는다. 재현하지 않았다면 재현 확인을 주장하지 않는다.
3. **민감 정보 제거**: 토큰, 개인 정보, 고객 문서 원문을 공개 이슈에 넣지 않는다. 공개하기 어려운 보안 취약점은 저장소의 현재 보안 제보 경로를 확인해 안내한다.
4. **중복 확인**: 접근 가능한 GitHub 이슈에서 같은 문제를 검색한다. 중복이면 기존 이슈와 차이를 정리한다.
5. **등록**: 사용자의 등록 요청과 GitHub 권한이 있으면 이슈를 생성한다. 앱이나 연결 도구에 이슈 생성 기능이 있으면 이를 사용하고, CLI를 쓴다면 [GitHub CLI 공식 `gh issue create` 문서](https://cli.github.com/manual/gh_issue_create)의 `--body-file`로 본문 파일을 전달한다. 레이블은 실제 저장소에 있는 것만 붙인다.
6. **확인**: 생성 결과의 번호·URL을 읽어 보고한다. 생성 명령이 모호하게 실패했다면 같은 제목의 이슈를 먼저 조회하고 중복 생성하지 않는다.

## 이슈 본문

```markdown
## 대상과 환경
- 플러그인·스킬:
- 앱·운영체제·버전:

## 문제 또는 제안
[사용자가 설명한 내용]

## 재현 절차와 관찰 결과
[버그인 경우에만, 확인되지 않은 단계는 미확인 표시]

## 기대 동작
[사용자 기대]

## 추가 자료
[공개 가능한 로그·화면·관련 이슈]
```

GitHub 연결이나 권한이 없으면 등록하지 못했다는 사실과 함께 복사 가능한 초안 및 `https://github.com/modu-ai/moai-cowork/issues/new`를 제공한다. 이슈 생성 전후 상태를 혼동하지 않는다.
