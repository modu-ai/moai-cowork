# 앱 푸시 기획 가이드 (Push Mode)

채널 메시지 엔진의 **앱 푸시 모드** 상세 참고자료. "앱 푸시 문구 만들어줘", "리텐션 푸시 카피" 같은 발화 시 이 가이드로 4원칙 + 3요소 + 변형 3안 + 성과 측정 계획을 적용한다. 짧은 잠금화면 카피는 push-copy.md(카테고리별 카피 패턴·발송 시점·빈도), 기획 프레임은 본 문서를 함께 본다.

## 푸시 4원칙 (발송 전 4질문)

| 원칙 | 질문 | 점검 기준 |
|------|------|----------|
| **WHY** (왜) | 발송 목적은 4분류 중 어디? | 서비스 노출 / 할인·이벤트 / 인지도 / 리텐션 |
| **WHEN** (언제) | 행동 또는 시간 트리거? | 행동 후 3분/3시간/3일 / 데일리 골든타임 / 시즌·이슈 |
| **WHO** (누구에게) | 세그먼트가 정의됐는가? | 전체 회원 / 코호트 / 1:1 개인화 |
| **HOW** (어떻게) | 톤앤매너가 명확한가? | 숫자 · 게이미피케이션 · 브랜딩 · 이모지 정책 |

> 4원칙 미충족 시 발송 금지 — 하나라도 답하지 못하면 차단. 무차별 푸시는 옵트아웃(앱 알림 OFF) 비율을 높여 장기 ROI를 깎는다.

## 3요소 자가 점검 (Timely · Personal · Actionable)

- **Timely**: 받았을 때 행동 가능한 상황인가? 발송 시간은 대상 고객의 실제 행동 데이터와 야간 광고 별도 동의 요건을 확인한다.
- **Personal**: 세그먼트·이름·구매 이력 반영? (전체 < 세그먼트 < 1:1)
- **Actionable**: 다음 액션이 명확한가? (탭 위치 + 시간 + 혜택)
  - ❌ "신상품 입고" → 무엇을? 어떻게?
  - ✅ "지금 탭 → 신상 30% 한정 진입 (10:00까지)"

> 세 요소는 문안 점검 기준이다. 클릭률 효과는 실제 캠페인 데이터로 측정하며, 자료 없이 상승폭을 예측하지 않는다.

## 발송 목적과 측정 지표

| 목적 | 문안에 필요한 확인 자료 | 측정 지표 |
|---|---|---|
| 서비스 안내 | 실제 기능·대상·이동 화면 | 관련 화면 방문율, 수신거부율 |
| 할인·이벤트 | 승인된 가격·기간·대상·재고 | 클릭률, 구매 전환율, 수신거부율 |
| 브랜드 소식 | 공개 가능한 사실·발송 목적 | 클릭률, 수신거부율 |
| 재방문 | 사용자 행동 데이터의 활용 범위와 동의 | 재방문율, 수신거부율 |

발송 빈도와 시간은 일률적인 업계 수치로 정하지 않는다. 셀러의 기존 발송 기록, 고객 시간대와 수신 동의를 확인한다.

## 문안 변형

같은 사실을 유지한 채 A/B 문안의 표현만 바꾼다. 실제로 확인되지 않은 할인율·마감·재고·개인화 혜택을 변형안에 추가하지 않는다.

| 변형 축 | 비교 예시 |
|---|---|
| 정보 순서 | 상품 특징 먼저 / 사용 상황 먼저 |
| 말투 | 간결한 안내 / 친근한 안내 |
| 행동 유도 | 기능 보기 / 상품 상세 보기 |

## 성과 측정

```text
기준값: 같은 채널·고객군의 이전 캠페인 CTR·전환율·수신거부율
실험: 대상·기간·혜택을 맞춘 두 문안 비교
기준값이 없으면: 예상 수치를 비워 두고 첫 캠페인 실측값을 기록
```
