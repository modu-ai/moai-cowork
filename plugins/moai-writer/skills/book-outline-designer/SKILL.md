# book-outline-designer

> 책의 구조와 장별 역할을 정리하는 스킬. 사용자가 이미 제공한 개요가 있으면 그대로 활용한다. 독자 자료가 없으면 가설이라고 표시하고, 실제 독자 반응이나 출판사 선호를 수치로 꾸미지 않는다.

## 1. 입력 확인

| 항목 | 확인할 내용 |
|------|-------------|
| 책의 목적 | 독자에게 전달할 주제·이야기 |
| 독자 | 실제 조사 결과와 저자의 가설 구분 |
| 원고 | 이미 쓴 장·꼭지와 저자가 유지하려는 순서 |
| 분량 | 저자의 목표, 측정 기준, 투고처 요구를 구분 |
| 투고처 | 정해져 있다면 현재 공식 제출 안내 확인 |

필수 자료가 없으면 질문 기능으로 묻는다. 질문 기능이 없는 환경에서는 누락된 항목을 적고 사용자가 답할 때까지 해당 결정을 보류한다. 다른 책 스킬 산출물이 없어도 제공된 자료로 진행할 수 있다.

## 2. 목차 설계

1. 각 장의 역할을 한 문장으로 적는다. 같은 내용을 반복하는 장은 합치거나 역할을 다시 정한다.
2. 독자가 이해하거나 따라갈 수 있는 순서로 장을 배치한다. 소설은 사건·시점·갈등의 의도를 저자에게 확인한다.
3. 부·장·꼭지는 책에 필요한 수준까지만 쓴다. 소설에도 꼭지를 둘 수 있고, 짧은 책에는 부가 없어도 된다.
4. 자료로 확인되지 않은 독자의 고민이나 결과는 목차의 확정 전제로 삼지 않는다.
5. 목차를 저자의 실제 원고·의도와 대조하고 바뀐 이유를 적는다.

### 장르별 검토 질문

| 장르 | 질문 |
|------|------|
| 실용서 | 독자가 필요한 설명과 실습이 순서대로 이어지는가? |
| 인문·에세이 | 글의 관점과 서사가 저자 의도에 맞는가? |
| 기술서 | 선행 지식·실습 환경·코드 버전의 순서가 맞는가? |
| 소설 | 사건·인물·시점의 흐름이 의도에 맞는가? |

장르만으로 부·장·꼭지 수나 시각 자료 개수를 정하지 않는다.

## 3. 분량 계획

사용자나 투고처가 지정한 목표와 실제 글자 수 계산 기준을 먼저 확인한다. 투고처가 공백 포함 200자 원고지 기준을 명시했다면 해당 범위의 글자 수를 200으로 나눠 참고 매수를 계산한다. 공백·제목·각주·표·그림 포함 여부는 투고처 지침에 따른다. 기준이 없으면 `매수 미확인`이라고 적는다. A4 쪽수나 단어 수에서 원고지 매수를 역산하지 않는다.

| 단위 | 저자 목표 | 투고처 요구 | 실제 측정 | 조정 이유 |
|------|-----------|-------------|-----------|-----------|
| 전체·부·장·꼭지 | 확인된 값 또는 미정 | 확인된 값 또는 미확인 | 초고가 있을 때만 | 내용에 따른 판단 |

장별 분량은 역할에 맞게 배분한다. 목표와 차이가 크더라도 임의 비율로 자동 분할하지 않고 저자와 조정한다.

## 4. 장별 시놉시스

각 장에서 다룰 내용과 다음 장과의 관계를 필요한 만큼 적는다. 아래 항목은 선택형이며 모든 장에 5요소·고정 글자 수를 강제하지 않는다.

- **시작**: 장면, 문제, 질문 중 장에 필요한 도입
- **전개**: 실제 주장·사례·사건과 확인된 근거
- **전환**: 있을 때만 변화의 이유
- **마무리**: 설명의 정리 또는 서사의 여운
- **연결**: 다음 장으로 이어질 필요가 있을 때만

확인하지 않은 통계·인터뷰·저자 경험을 사례란에 채우지 않는다. 필요한 자료는 `추가 확인`으로 남긴다.

## 5. 흐름 검토

목차를 앞·중간·끝에서 읽으며 주제 누락, 반복, 설명 순서, 저자의 문체와 의도를 점검한다. 실제 독자 반응을 조사하지 않았으면 흥미·신뢰·완독률을 퍼센트로 평가하지 않는다. 검토 결과는 `저자 확인 필요`, `자료 확인 필요`, `구조 수정 제안`으로 구분한다.

## 6. 출력 형식

```markdown
# 도서 목차 초안 — [가제]

- 확인된 입력: [저자가 제공한 사실]
- 독자 가설·미확인: [내용]
- 목표 분량과 계산 기준: [확인된 경우만]
- 투고처 요구: [현재 공식 안내에서 확인한 값 또는 미확인]

## 목차
[책에 필요한 수준의 부·장·꼭지]

## 장별 시놉시스
| 장 | 역할 | 주요 내용·근거 | 추가 확인 |
|----|------|----------------|-----------|
| [장] | [역할] | [확인된 내용] | [없는 자료] |

## 구조 검토
- 반복·누락: [근거]
- 순서 조정: [제안과 이유]
- 저자 확인 사항: [질문]
```

## 7. 투고처와 자료

대상 출판사나 공모가 정해지면 현재 공식 안내에서 목차·시놉시스의 분량, 파일 형식, 접수 경로와 마감일을 확인한다. 다른 책의 목차나 과거 공모 양식을 현재 출판사의 의무 양식으로 단정하지 않는다. 개인 Obsidian vault의 존재나 접근 권한을 전제하지 않는다. 사용자가 제공한 자료는 실제 읽은 범위에서만 반영한다.

## 8. 관련 스킬

- `book-concept-planner`: 책의 목적·차별점이 필요한 경우
- `book-target-reader`: 독자 자료나 가설을 정리할 경우
- `book-chapter-writer`: 장별 초고가 필요한 경우
- `book-proposal-writer`: 투고처 조건을 확인한 뒤 제안서를 만들 경우
- `moai-writer:korean-spell-check`: 공개 서비스 이용 조건·문서 공개 범위·사용자 의사를 확인한 경우
- `moai-coworker:ai-slop-reviewer`: 설치·노출됐고 필요한 경우
- `moai-writer:korean-humanize`: 필요한 경우 윤문 뒤 원문 의미와 근거를 대조
