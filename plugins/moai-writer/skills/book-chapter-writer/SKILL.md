# book-chapter-writer

> 도서 본문을 꼭지 단위로 집필하는 스킬. 사용자가 제공한 개요와 자료를 바탕으로 핵심 메시지와 예시의 순서를 정하고 초고를 작성한다. 분량·인용·도표·코드의 요구 사항은 대상 출판사와 원고의 성격에 맞춰 확인한다. 초고는 저자의 사실 확인과 권리 검토를 거쳐야 한다.

## 1. 개요

본문은 사용자가 지정한 꼭지 또는 장 단위로 쓴다. 다음 요소는 구성 예시이며 장르와 시놉시스에 맞게 생략하거나 순서를 바꾼다:

| 요소 | 역할 |
|------|------|
| **도입** | 독자가 따라올 수 있도록 장면이나 문제를 제시 |
| **전개** | 주제에 필요한 주장·사례·근거 또는 사건을 전개 |
| **전환** | 필요한 경우 관점이나 사건의 변화를 제시 |
| **마무리** | 꼭지의 목적에 맞게 정리하거나 여운을 남김 |
| **연결** | 필요한 경우 다음 꼭지·장으로 이어짐 |

원고지 매수는 단어 수로 환산하지 않는다. 먼저 투고처의 글자 수·공백·표·그림 계산 기준을 확인한다.

## 2. 트리거 키워드

자동 호출 트리거 (frontmatter description 참조). 슬래시 호출: `/book-chapter-writer`.

## 3. 워크플로우 (4단계)

### Step 1: 꼭지 시놉시스 확장

book-outline-designer의 장 단위 시놉시스에서 작성할 꼭지 1개를 선택한다. 기존 자료에 없는 항목은 현재 런타임의 사용자 질문 기능으로 확인한다. 질문 기능이 없는 실행 환경에서는 누락된 항목을 명시하고 사용자 입력을 기다린다:

| 항목 | 질문 |
|------|------|
| 꼭지 위치 | 몇 장 몇 꼭지? (예: "2장 3꼭지") |
| 목표 분량 | 사용자가 지정한 글자 수 또는 투고처 기준의 매수 |
| 주제 한 줄 | 이 꼭지가 다룰 한 문장 |
| 페르소나 시점 | 어떤 페르소나를 가정해 쓸 것인가? |
| 인용·자료 | 인용할 자료·도표·코드 미리 정리 |

### Step 2: 꼭지 골격 작성

확장된 시놉시스에 맞춰 필요한 요소만 배치한다. 아래는 실용서 구성 예시다:

```
[훅] (1~2 문장)
[훅에서 본문 도입으로 자연스러운 다리]

[본문 단락 1] (핵심 주장 1)
- 근거 1
- 사례·인용 1

[본문 단락 2] (핵심 주장 2)
- 근거 2
- 사례·인용 2

[본문 단락 3] (핵심 주장 3 — 선택)
- 근거 3
- 사례·인용 3

[클라이맥스] (가장 강력한 통찰·인용·결론)

[정리] (한 줄 요약 + 실천 제안)

[다음 연결] (다음 꼭지·장 예고)
```

### Step 3: 장르와 저자 문체 적용

§4의 문체 예시를 참고하되 저자의 기존 문체와 대상 독자를 우선한다.

### Step 4: 분량 카운트·인용·도표 처리

#### 분량 카운트 (200자 원고지)

- 실제 본문 글자 수를 문서 편집기 또는 문자 수 계산 기능으로 확인한다. 수치를 측정하지 못했다면 추정치라고 표시한다.
- 투고처가 공백 포함 글자 수를 200으로 나누도록 정했다면 `측정한 글자 수 ÷ 200`으로 매수를 환산한다. 예를 들어 공백 포함 800자는 4매다.
- 공백, 제목, 각주, 표·그림의 포함 여부는 투고처의 현재 지침을 확인한다. 기준이 없으면 글자 수와 계산 기준을 함께 적고 매수는 참고치로 표시한다.

#### 인용·각주 처리

| 인용 유형 | 표기 |
|----------|------|
| 짧은 인용 (1-2 문장) | 따옴표("…") |
| 긴 인용 (3 문장 이상) | 들여쓰기 인용 단락 + 출처 |
| 통계·데이터 | 본문 인용 + 각주에 출처 |
| 인터뷰·발언 | 발언자 + 매체 + 날짜 명시 |
| 인터넷 자료 | 접속일 + URL 각주 |

#### 도표·코드·이미지 자리표시

| 자료 | 자리표시 |
|------|----------|
| 도표 | `[도표 X-Y. 도표 제목]` (X=장, Y=순번) |
| 코드 | ` ```language ... ``` ` (기술서) |
| 스크린샷 | `[그림 X-Y. 그림 제목]` |
| 인포그래픽 | `[인포그래픽 X-Y]` |
| 실습 박스 | `> **실습**: …` |
| 체크리스트 | `- [ ] 항목` |

## 4. 장르별 문체 참고

### 4-1. 실용서·자기계발

| 차원 | 분기 |
|------|------|
| 문체 | **명료·실용·약속 중심** |
| 어미 | 저자의 선택에 따라 일관되게 조정 |
| 문장 길이 | 독자가 이해하기 쉬운 길이 |
| 단락 길이 | 설명의 흐름에 따라 조정 |
| 사례 | 확인된 사실만 사용하고 가상 사례는 명시 |
| 시각 자료 | 이해에 도움이 될 때 도표·체크리스트·실습 박스 사용 |
| 어조 | 친근하고 격려하는 톤 (선생님→학생) |

훅 예시 패턴:
- 질문형: "○○해본 적 있나요?"
- 통계형: 출처와 조사 조건을 확인한 수치로 시작
- 시나리오형: "오늘 아침 ___를 발견했다면…"

| 차원 | 분기 |
|------|------|
| 문체 | **서사·문체 중심·은유 활용** |

| 문장 길이 | 다양 (짧은 문장과 긴 문장 교차) |
| 단락 길이 | 장면과 문체에 따라 조정 |

| 시각 자료 | 적음 (사진·삽화 정도) |
| 어조 | 사색적·고백적·따뜻함 |

훅 예시 패턴:
- 장면 묘사: "___의 어느 날, 나는 ___" 
- 인용 도입: "○○○ 작가는 이렇게 말했다…"
- 질문 도입: "왜 사람들은 ___일까?"

### 4-3. 기술·전문서·IT 입문서

| 차원 | 분기 |
|------|------|

훅 예시 패턴:
- 문제 정의: "___를 만들 때 자주 마주치는 문제는…"

## 6. 사용 예시

### 예시 1 — 실용서 (부업서 꼭지)

```
book-outline-designer 출력: 2장 3꼭지 "30일 챌린지 시작하기" 시놉시스.
이 꼭지 본문 작성. 4매 (800자).
```

→ 훅: "지금 할 수 있는 일을 하나씩 적어 보자."
→ 본문: 30일 챌린지의 자기진단·채널 선택·실행 순서와 저자가 제공한 사례
→ 전환: 실행 과정에서 확인한 문제와 다음 선택
→ 정리: "30일 챌린지의 핵심은 시작이 아니라 멈추지 않는 것."  
→ 다음 연결: "다음 꼭지에서는 채널을 고르는 기준을 다룬다."
→ 필요한 경우 체크리스트 자리표시

### 예시 2 — IT 입문서 (Next.js 꼭지)

```
"Next.js 15 App Router 첫 페이지 만들기" 꼭지 본문 작성. 8매 (1,600자).
주니어 3년차 개발자 페르소나.
```

→ 훅: "Pages Router에 익숙하던 우리에게 App Router는 새로운 패러다임이다." (문제 정의)  
→ 본문: 1) App Router 폴더 구조 / 2) 첫 page.tsx 작성 / 3) 동작 확인  
→ 설명에 필요한 코드 블록과 실행 결과
→ 클라이맥스: "App Router의 핵심은 서버 컴포넌트가 기본이라는 것이다."  
→ 정리: "App Router 폴더, page.tsx, 동작 확인 순서를 다시 짚는다."
→ 다음 연결: "다음 꼭지에서는 layout.tsx로 공통 레이아웃을 다룬다."

### 예시 3 — 에세이 (워킹맘 꼭지)

```
"새벽 5시, 카페에서 만난 나" 에세이 1장 본문 작성. 5매 (1,000자).
40대 워킹맘 시점.
```

→ 훅: "새벽 5시. 동네 24시 카페의 형광등은 차갑게 푸르다." (장면 묘사)  
→ 본문: 새벽에 글을 쓰러 나오는 일상 + 그 자리에서 만난 자기 자신 +"엄마"라는 호칭에 대한 사유  
→ 인문 프리셋 → 서사·은유·문체 일관성

## 7. 한국 출판 본문 컨벤션

### 분량 확인

투고처가 원고지 200자 기준과 포함 범위를 명시했다면 그 기준으로 글자 수를 나눠 참고 매수를 계산한다. 책의 쪽수나 A4 장수로 원고지 매수를 역산하지 않는다. 한국출판문화산업진흥원의 한 공모는 200자 원고지 400매를 공백·그림 등을 포함한 약 80,000자로 명시했지만, 이는 해당 공모의 제출 기준이다. 다른 투고처에 그대로 적용하지 않는다.

### 한국어 문체 유의 사항

1. **어미** — 저자의 의도와 독자에 맞춰 일관성을 살피되 인용·대화·문맥상의 변화를 허용
2. **한자어 → 우리말** — 가능한 우리말 표현 우선 (예: "발휘" → "발휘된다" 대신 "드러난다")
3. **인용 부호** — 한국 표준 따옴표 "" ' '
4. **외래어 표기** — 국립국어원 외래어 표기법 (예: "콘텐츠" 아닌 "컨텐츠"는 잘못)
5. **숫자 표기** — 독자가 읽기 쉬운 표기를 선택하고 원고 안에서 일관되게 사용

### 투고처 양식

대상 출판사나 공모의 현재 공식 제출 안내에서 파일 형식·분량·문체·인용 방식을 확인한다. 확인되지 않은 선호 어미나 양식을 출판사 관행으로 단정하지 않는다.

## 8. 주의사항

### 본문 함정 회피

| 함정 | 피하는 법 |
|------|----------|
| **분량 차이** | 사용자나 투고처의 목표와 실제 측정치를 비교하고 수정 범위를 협의 |
| **문체 불일치** | 저자 의도와 독자에 맞게 일관성을 검토 |
| **인용 표기 누락** | 모든 인용·통계·발언에 출처 명시 |
| **추상어 남용** | 필요한 부분만 확인된 사례나 설명으로 구체화 |
| **상투적 표현** | 완성된 초고를 원문 자료와 대조하고 필요하면 윤문 |
| **한자어 과다** | 우리말 우선, 한자어는 정확한 용어일 때만 |
| **투고처 양식 미확인** | 현재 공식 제출 안내에서 요구 사항 확인 |

### 인용·저작권 주의

- **직접 인용의 표시**: 인용 가능 여부를 먼저 확인한 뒤 짧은 문장은 따옴표와 출처, 긴 문장은 별도 단락과 출처로 구분한다. 표기만으로 이용 허락이나 적법성이 확인되지는 않는다.
- **공표된 저작물의 인용**: 저작권법 제28조는 목적·정당한 범위·공정한 관행을 함께 요구한다. 출처 표시만으로 적법성이 확정되지 않으므로 인용의 필요성·분량·이용 허락 여부를 개별 확인한다.
- **외부 참고 자료**: 이용 허락이나 적법한 인용 근거를 확인하지 못한 문장은 그대로 옮기지 않는다.
- **이미지·도표**: 자체 제작 여부 또는 해당 라이선스와 이용 조건을 확인
- **인터뷰 발언**: 공개 범위와 이용 허락을 확인하고 발언자·출처를 명시

### 분량 관리

- **목표 분량**: 지정된 계산 기준으로 확인하고 차이가 크면 분할·통합을 제안
- **꼭지 분량**: 각 꼭지의 역할에 맞춰 조정

### 출처 정책

- 실제 자료에서 가져온 인용·통계·사례의 **출처 명시**. 창작 장면과 가상 사례는 실제 사실처럼 쓰지 않는다.
- vault를 포함한 외부 자료는 허락이나 적법한 인용 근거 없이 전재하지 않는다. 조건을 확인한 직접 인용은 출처와 원문 구분을 유지한다.
- 본문 작성 후 **인용·각주 정리표** 별도 출력 권장
