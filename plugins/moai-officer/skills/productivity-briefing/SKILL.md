# 업무 브리핑

## 범위 설정

업종, 관심 기업·키워드, 지역, 기준 시각과 기간을 확인한다. 사용자가 원하는 항목만 담는다. 실제 자료에 접근하지 못한 항목은 비워 두거나 미확인으로 표시한다. 사용자의 캘린더·할 일 목록은 연결된 자료를 확인한 경우에만 포함한다.

## 조사

1. 뉴스는 기사 발행일과 사건 발생일을 구분한다. 원문 링크와 매체를 남긴다.
2. 규제·정책은 해당 기관의 공고, 법령, 시행일, 적용 대상을 확인한다. 기사 해설만으로 법률 효과를 단정하지 않는다.
3. 시장 지표는 공식 거래소·중앙은행·통계기관 등의 수치와 관측 시각·단위·전일 대비 기준을 확인한다. 실시간 수치 접근이 없으면 추정치를 넣지 않는다.
4. 경쟁사 정보는 공개된 제품 공지·보도자료·채용 공고·공시 등을 사용한다. 사이트 변경이나 채용만으로 매출 부진·신사업 확정·고객 만족도를 추론하지 않는다. 신분을 숨긴 문의나 사칭으로 내부 정보를 얻도록 안내하지 않는다.
5. 서로 다른 출처가 충돌하면 어느 수치·날짜가 다른지 표시하고 확인되지 않은 결론을 남긴다.

## 작성 형식

```markdown
# [기준일·시간] [업종] 브리핑

## 핵심 변화
- [확인된 사실] — [원문 링크, 발행일 / 사건일]

## 우리 업무와의 관계
- [영향 가능성] — [근거와 전제]
- [확인할 질문]

## 지표
| 항목 | 값 | 기준 시각·단위 | 출처 |

## 다음 행동
- [ ] [근거가 있는 검토·확인 작업]
```

관련 자료가 없으면 섹션을 억지로 채우지 않는다. 시사점은 사실과 분리해 추론이라고 밝힌다. 예시 회사·주가·환율·정책·뉴스를 실제 오늘의 브리핑처럼 제시하지 않는다.

## 검수와 저장

- 링크가 해당 주장에 직접 연결되는지, 날짜·숫자·단위·인용이 원문과 맞는지 다시 확인한다.
- 유료·비공개 자료는 접근 권한과 인용 범위를 지킨다.
- 파일 저장이나 정기 실행은 현재 호스트의 해당 기능과 사용자의 저장 위치·주기를 확인한 뒤 실행한다. 저장하지 않았다면 브리핑 파일이 있다고 주장하지 않는다.
