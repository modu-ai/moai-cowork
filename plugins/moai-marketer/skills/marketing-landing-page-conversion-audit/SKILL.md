# 랜딩페이지 전환 점검

기존 페이지를 관찰해 전환을 막을 수 있는 가설을 찾습니다. 새 랜딩 제작은 marketing-landing-page, 이커머스 상세페이지는 moai-seller의 해당 스킬로 연결합니다.

## 필요한 자료

- 현재 랜딩 URL 또는 화면 자료와 어떤 기기·국가·브라우저에서 볼지
- 연결된 광고 문구와 실제 클릭 후 도착 URL
- 분석 기간, 유입 채널별 방문·주요 행동·구매 또는 신청 지표의 분모와 출처
- 상품 가격·배송·환불·보증·후기·인증 등 확인된 근거

접근 권한이 없으면 제공된 화면만으로 판단한 범위를 밝힙니다. 화면을 열지 못했으면 화면 검토를 했다고 쓰지 않습니다.

## 점검 순서

1. 광고의 약속과 도착 페이지의 상품·혜택·조건이 일치하는지 확인합니다. 단어가 똑같아야 하는 것은 아니지만 의미와 조건이 달라서는 안 됩니다.
2. 대상 고객이 첫 화면에서 제공 가치와 다음 행동을 이해할 수 있는지 확인합니다.
3. 가격·배송·환불·개인정보 처리·문의 경로가 실제 정책과 일치하고 찾기 쉬운지 봅니다.
4. 후기·평점·수치·전후 사진은 출처와 사용권을 확인합니다. 없는 사회적 증거를 만들거나 환불 보장을 새로 약속하지 않습니다.
5. 모바일과 데스크톱에서 입력·버튼·결제 또는 신청 경로를 직접 확인할 수 있으면 동작을 기록합니다. 권한·환경이 없으면 미검증으로 둡니다.
6. CTR·전환율·이탈률은 같은 기간과 세그먼트의 분모를 확인해 비교합니다. 높은 클릭률과 낮은 전환율만으로 랜딩을 단독 원인으로 판정하지 않습니다.

## 결과

| 관찰 | 증거·화면 위치 | 고객 영향 가설 | 개선안 | 필요한 확인 | 우선순위 |
|---|---|---|---|---|---|
| 실제로 확인한 항목 | URL·화면·데이터 | 추정이라고 표시 | 실행 가능한 변경 | 측정·정책·개발 확인 | 근거 |

문제·가설·확인된 원인을 구분합니다. 임의의 총점이나 예상 전환 상승률, 고정 단계별 일정은 제시하지 않습니다. 개선안을 적용한 뒤에는 실제 지표를 비교하거나 실험을 설계합니다. 서술 검수 스킬이 설치돼 있으면 활용하되 원문과 수치를 대조하고, 없으면 직접 검수합니다.

## 연결

- content-copywriting: 확인된 상품 조건에 맞춘 헤드라인·CTA 초안
- marketing-landing-page: 신규 랜딩 구현
- marketing-growth-experiment: 변경 효과를 확인할 실험 설계
- marketing-performance-report: 실제 성과 비교
