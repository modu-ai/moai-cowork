# 뉴스레터 작성

독자, 발행 목적, 주기, 브랜드 문체, 이번 호 주제, 사용자 제공 자료와 현재 구독 상태를 확인한다. 뉴스·통계·인용·링크는 원출처와 발행일을 확인한다. 업계 동향을 실시간 조회하지 못했다면 확인하지 못했다고 적는다.

## 원고

1. 제목은 본문이 실제로 전달하는 내용을 요약한다. 수신자 이름이나 긴급성을 근거 없이 넣지 않는다.
2. 프리헤더는 제목을 보완한다. 본문은 핵심 정보, 출처, 독자의 다음 행동이 필요한 경우 그 행동을 담는다.
3. 사용자가 제공한 경험과 편집자의 해석을 사실 보도와 구분한다. 제공되지 않은 독자 사례나 성과를 만들지 않는다.
4. 광고성 정보가 포함되면 [정보통신망법 제50조](https://law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1025127785)와 [KISA 안내서](https://spam.kisa.or.kr/spam/na/ntt/selectNttInfo.do?bbsId=1002&mi=1020&nttSn=3001)를 기준으로 발송 주체·동의·표시·거부 절차를 확인한다. 유료 구독과 계약상 제공 정보의 구분은 실제 내용과 계약을 검토한다.
5. 제목·본문·링크·모바일 렌더링·수신 거부 절차를 검수한다.

## 발행 경로

이 플러그인의 WordPress.com MCP는 웹 아카이브용 게시물 초안을 만들 수 있다. 연결·대상 사이트·권한을 확인한 뒤 사용자의 요청 범위에서 초안을 저장하고, 공개 게시 전 승인 범위를 확인한다. **웹 게시물이 구독자 이메일로 발송됐다는 뜻은 아니다.** 실제 이메일 발송은 사용 중인 발송 서비스의 연결과 대상 목록을 별도로 확인한다. 연결이 없다면 복사 가능한 원고를 제공한다.

오픈율·구독자 증가 효과를 제목 패턴으로 보장하지 않는다. 발송 후 실제 발송·열람·클릭 자료가 있으면 다음 호의 주제와 구성에 반영한다. 자세한 편집 절차는 [뉴스레터 참고](references/newsletter-engine.md)를 따른다.
