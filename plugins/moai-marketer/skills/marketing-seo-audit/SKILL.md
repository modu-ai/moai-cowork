# SEO 감사

검색 채널과 고객의 실제 유입 경로를 확인한 뒤 사이트·블로그·플레이스의 관측 가능한 문제를 찾는다. 네이버, 구글, AI 답변 서비스의 결과와 정책을 같은 순위표로 합치지 않는다.

## 범위와 근거

1. 대상 URL, 사업 지역, 목표 검색어와 고객 행동을 확인한다.
2. 공개 페이지를 직접 열어 제목·본문·내부 링크·접근성·모바일 표시를 본다.
3. 권한이 있으면 네이버 서치어드바이저, Google Search Console, 분석 도구의 날짜·검색어·페이지 자료를 확인한다. 접근이 없으면 제출 여부, 순위 변화, 트래픽, 전환을 추정하지 않는다.
4. 검색 결과는 위치·로그인·시점에 따라 달라질 수 있으므로 관찰 조건을 기록한다.
5. 각 발견을 `확인된 문제`, `추가 확인 필요`, `개선 가설`로 나누고 근거 URL 또는 화면을 남긴다.

검색량·경쟁도는 해당 도구의 실제 수치와 기준 기간이 있을 때만 적는다. 키워드 제안은 검색 의도와 관련 페이지를 함께 기록한다.

## 네이버

[네이버 C-Rank 설명](https://help.naver.com/service/5626/contents/22927?osType=COMMONOS)은 출처의 관심사 집중도·정보 품질·소비와 생산의 반응을 종합한다고 설명한다. [D.I.A. 설명](https://help.naver.com/service/5626/contents/22926?osType=COMMONOS)은 문서의 경험과 검색 의도에 관한 안내다. 내부 가중치나 개별 블로그 점수는 공개 자료만으로 계산할 수 없다.

- 검색어별 실제 노출 페이지, 문서의 관련성, 직접 확인 가능한 경험·근거·최신 정보를 점검한다.
- 게시 주기, 글자 수, 사진 수, 특정 주제 외 게시 여부를 고정 순위 규칙으로 쓰지 않는다.
- 순위 변화는 관측 기간과 검색 결과 증거를 제시한다. AI로 썼다는 이유만으로 자동 페널티를 단정하지 않는다.
- 네이버 플레이스가 필요한 업종이면 `references/naver-place.md`를 함께 적용한다.

## 구글

색인 가능성, 대표 URL, 모바일 렌더링, 사이트맵, robots.txt, 메타 태그, 내부 링크, 구조화 데이터의 실제 적용 여부를 확인한다. robots.txt가 접근을 막는지와 페이지가 색인되었는지는 별개로 검증한다.

[Google의 유용한 콘텐츠 안내](https://developers.google.com/search/docs/fundamentals/creating-helpful-content)는 독창성과 신뢰를 강조하며 E-E-A-T 자체는 단일 순위 요소가 아니라고 설명한다. 작성자의 경험·전문성과 출처는 실제로 검증 가능한 경우에 제시한다. 제목 글자 수, 메타 설명 글자 수, 키워드 밀도, 내부 링크 개수를 보편적인 통과 기준으로 쓰지 않는다.

[Core Web Vitals 안내](https://web.dev/articles/vitals)의 권장값은 LCP 2.5초 이하, INP 200ms 이하, CLS 0.1 이하이며 모바일·데스크톱의 현장 데이터 75번째 백분위수 기준으로 본다. 측정값이 없으면 통과·실패를 적지 않는다. 실험실 수치와 현장 수치를 구분한다.

## AI 검색 노출

[Google의 AI 검색 안내](https://developers.google.com/search/docs/appearance/ai-features)에 따르면 AI Overviews·AI Mode용 별도 필수 최적화는 없다. 검색 색인과 스니펫 적격성, 기본 SEO를 확인한다. Google 검색의 크롤링 제어는 Googlebot 정책을 보고, AI 학습용 크롤러 정책과 혼동하지 않는다. `llms.txt`나 특정 스키마를 필수 요건으로 적지 않는다.

ChatGPT·Perplexity 등 다른 서비스의 인용은 실제 질의·응답과 출처를 관찰할 수 있을 때만 기록한다. 색인에 걸리는 기간이나 인용 보장은 제시하지 않는다. 자체 데이터와 분명한 출처를 싣되, 단정형 문장을 양산하거나 근거 없는 통계를 만들지 않는다.

## 네이버 플레이스

오프라인 사업장이나 예약·방문이 중요한 경우 실제 업체 페이지를 보고 다음을 확인한다.

- 업체명·업종·주소·영업시간·연락처·메뉴·사진 등 고객에게 필요한 정보의 정확성
- 적용 가능한 예약·주문·문의 기능과 실제 운영 가능 여부
- 리뷰 응대의 사실성, 개인정보 보호, 대가 제공 시 표시와 플랫폼 정책
- 광고 집행 여부와 별도로 검색 노출·예약·방문 성과를 측정할 수 있는지

세부 항목은 `references/naver-place.md`를 읽는다. 업체 계정에 접근하지 못하면 편집 가능 여부와 계정 내부 지표를 미확인으로 둔다.

## 우선순위와 보고서

발견마다 영향받는 페이지·사용자 문제·근거·수정 난도·담당자·확인 방법을 붙인다. 색인 불가나 잘못된 업체 정보처럼 확인된 사용자 피해를 먼저 다룬다. 날짜별 순위와 전환 변화는 기준선과 측정 도구가 있을 때만 평가한다. 증거 없이 네이버·구글·AI 검색의 종합 점수나 임의의 별점을 만들지 않는다.

보고서는 범위와 접근 권한, 채널별 발견, 미검증 항목, 추천 검색어와 의도, 우선순위별 조치, 재측정 계획으로 구성한다. 사이트에 접근할 수 없으면 일반 가이드와 필요한 자료 목록을 분리해 제공한다.

서술형 권고는 원래 근거와 대조해 사실·의미·표현을 직접 검수한다. `moai-coworker:ai-slop-reviewer`와 `moai-writer:korean-humanize`가 설치돼 있으면 보조로 사용하고 다시 근거와 대조한다. 수치·표·URL은 윤문 대상이 아니다.
