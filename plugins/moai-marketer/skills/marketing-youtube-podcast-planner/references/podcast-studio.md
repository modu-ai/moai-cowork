# 팟캐스트 에피소드 제작

## 기획과 조사

청중이 알고 싶어 하는 질문, 에피소드의 핵심 주장, 솔로·인터뷰·토론 형식, 녹음 여건을 정한다. 최신 자료가 필요한 사실·통계·인물 정보는 원출처와 날짜를 확인한다. 확인하지 못한 내용은 대본의 확정 사실로 넣지 않는다. 게스트의 발언은 실제 인터뷰 전까지 예상 답변으로 만들지 않는다.

## 대본과 녹음

오프닝에서 다룰 질문을 알리고, 본문을 이해 가능한 순서로 배열한다. 질문·전환·음원·효과음·광고 구간을 표시하되, 고정 길이나 첫 30초 후크를 필수 성과 공식으로 쓰지 않는다. 게스트 참여·녹음·공개 동의와 타인의 음원·이미지 권리를 확인한다.

## 쇼노트

제목, 실제 에피소드 요약, 확인한 출처 링크, 게스트 소개, 청취자가 사용할 자료를 넣는다. 녹음이나 최종 편집 파일이 없으면 타임스탬프와 인용문은 `예정`으로 표시하거나 비워 둔다. 편집 후 파일을 재생해 구간 시작 시간과 인용문을 확인한다.

## 배포

호스팅 서비스, RSS 공개 여부, 제출할 플랫폼, 계정 권한을 확인한다. [Spotify for Creators RSS 안내](https://support.spotify.com/dm/creators/article/your-rss-feed/)에 따르면 Spotify에 호스팅된 쇼도 다른 청취 플랫폼에는 별도 제출이 필요하다. RSS 이메일 노출과 플랫폼별 심사·공개 상태도 확인한다. 발행 예정일과 실제 공개일을 구분한다.

## 검수

조사 근거 → 녹음된 내용 → 대본·쇼노트 → 배포 문구의 연결을 확인한다. 실제 녹음과 다른 제목·인용·성과를 고친다. 검수 전 또는 배포 계정에 접근하지 못한 경우 결과를 초안·미확인으로 표시한다. 에이전트 분담이 가능한 환경에서만 역할을 나눌 수 있으며, 그렇지 않아도 동일한 검수 순서를 따른다.
