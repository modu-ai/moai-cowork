# 카피 검수와 웹 문구

## 주장 점검

- 누가 어떤 조건에서 얻는 혜택인지 문구에 드러나는가?
- 성능·효과·절감액·후기·순위·수상·한정 판매에 현재 근거가 있는가?
- 비교 대상과 기준이 명확한가?
- 클릭 뒤 페이지에서 실제 가격, 제한 조건, 신청 방법이 일치하는가?
- 업종별 광고 심의나 별도 표시가 필요한가?

근거 없는 최상급이나 숫자를 새 숫자로 바꾸지 않는다. 표현을 낮추거나 필요한 증빙을 요청한다. [공정거래위원회 부당 표시·광고 안내](https://www.ftc.go.kr/www/contents.do?key=700)의 유형과 해당 업종 규정을 확인한다.

## 한국어 문장

번역투·상투어·기계적인 반복은 실제 독자의 문맥에서 다듬는다. 비유·반말·2인칭·문장 길이를 모든 브랜드에 강제하지 않는다. 실제 고객 발언은 정확히 인용하고, 없는 후기를 만들지 않는다. 정보 문구의 날짜·가격·조건·인용은 문체를 바꾸면서도 보존한다.

## HTML 문구 수정

실제 파일을 수정할 때는 원본을 읽고 바꿀 텍스트 위치를 확인한다. 텍스트 노드·접근성 이름·제목·메타 설명·구조화 데이터 중 같은 메시지를 공유하는 위치를 찾아 일관되게 갱신한다. HTML·JSON 구문을 파손하지 않도록 해당 파일 형식의 파서나 빌드로 확인한다. 정규식 전체 치환은 속성·스크립트·코드를 잘못 바꿀 수 있으므로 대상으로 검증된 경우에만 사용한다.

과거 설계 노트의 before/after 예시는 실측 성과나 현재 제품 약속이 아니다. 자연화 스킬을 사용하더라도 사실 앵커와 사용자 승인을 보존한다.
