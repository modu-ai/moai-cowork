# 랜딩페이지 제작 범위

이 문서는 캠페인 랜딩을 요청받았을 때 필요한 작업을 정리합니다. 결과물이 곧바로 배포 가능하다고 가정하지 않습니다.

## 산출물 선택

- 카피 요청: 확인된 상품 조건을 담은 섹션별 문안과 행동 문구
- 설계 요청: 대상 고객, 필요한 섹션, 콘텐츠·이미지 목록, 화면 구조
- 구현 요청: 기존 저장소와 프레임워크에 맞는 파일·스타일·상호작용
- 배포 요청: 실제 호스팅·도메인·폼·결제·분석 설정과 권한 확인 후 검증

페이지 유형은 제품 출시·이벤트·상담·리드 수집 등으로 다양합니다. 섹션 개수와 순서는 목표와 자료에 맞춰 정합니다. 후기·가격표·카운트다운·재고 알림은 실제 근거와 기능이 있을 때만 사용합니다.

## 구현 경계

기존 사이트가 있으면 그 구조를 따릅니다. 새 단일 페이지는 HTML로도 만들 수 있고, 복잡한 상호작용이 필요하면 프로젝트에 맞는 프레임워크를 선택합니다. 폴더 트리, 프레임워크 버전, 이미지 용량, 제목 글자 수를 고정하지 않습니다. [Google Search의 지원 메타 태그 문서](https://developers.google.com/search/docs/crawling-indexing/special-tags)에 따르면 meta keywords는 Google 검색 순위에 영향을 주지 않습니다.

## 검증

실제 페이지를 열어 주요 화면 폭, 링크, 폼, 접근성, 이미지, 가격·조건을 확인합니다. 연결되지 않은 폼이나 결제는 미구현으로 표시합니다. 검색 순위·전환율·배포 완료는 각각 별도 증거가 있어야 보고합니다.
