# story-character-sheet: 캐릭터 비주얼 시트 + 일관성 앵커

캐릭터 외형을 일관되게 관리할 시트를 만드는 스킬이다. 서사 정보(성격·역할·말투)와 비주얼 시트(이미지 생성용 외형 디테일)를 함께 정리하고, 화마다 지킬 **일관성 앵커**를 적는다. 이 시트는 이미지 참조나 요청 시 Soul ID 학습의 시드가 되고, `story-webtoon-qc`가 일관성을 살피는 기준이 된다.

## 1. 개요

이 스킬은 **"무엇을, 어떤 외형으로, 무엇을 고정할지"**를 정한다. 실제 이미지 생성이나 Soul ID 학습을 실행하지 않는다. 사용자가 이미지 생성을 요청하면 현재 앱의 이미지 도구 또는 지정한 Higgsfield 공식 연결을 확인해 실행 단계로 넘긴다.

## 2. 이 스킬이 하지 않는 것

- **이미지 생성·Soul ID 학습 실행 안 함** — ChatGPT에서는 현재 앱에 노출된 기본 이미지 도구를 확인한다. Higgsfield 또는 Soul 지정 시 공식 연결의 실제 도구·비용·권한을 확인한다.
- **크레딧 수치 단정 안 함** — 사용자가 Higgsfield 경로를 택했을 때만 실제 연결의 비용 확인 결과를 따른다.
- **컷 프롬프트 조립 안 함** — 컷별 작화 프롬프트는 `story-webtoon-art` 소관. 이 스킬은 캐릭터 참조까지만.
- **회차 서사 안 씀** — 스토리 본문은 `story-webtoon-episode` / `story-webnovel-writer`.

## 3. 워크플로우

### Step 1 — 서사 정보 정리

성격 키워드(3개 이내)·역할·말투·"독자가 이 캐릭터를 좋아하는 이유"를 정리한다. 외형 디테일은 여기 섞지 않고 Step 2 비주얼 시트에 모은다(비주얼-서사 분리).

### Step 2 — 비주얼 시트 작성 (인물 8항목 / 동물 8항목)

인물이면 인물 8항목 표, 동물이면 동물 8항목 표를 채운다. 표 골격·레귤러/게스트 2계층 예산은 `references/visual-sheet-tables.md`.

### Step 3 — 일관성 앵커 결정 (짧고 필수)

비주얼 시트 항목 중 **화마다 반드시 고정할 1~2가지**를 정한다.

- 예: `은발 + 왼쪽 눈 밑 점`, `치즈태비 + 빨간 방울 목걸이`.
- 앵커가 흔들리면 캐릭터 구별이 어려워질 수 있다. 필요한 고정 외형은 참조 이미지와 컷 프롬프트에 적고 생성 결과를 확인한다(`references/neutral-base-rule.md`).
- 이 앵커는 `story-webtoon-qc`가 "일관성 위반 0건"을 판정하는 기준으로 소비한다 — 반드시 명시적으로 적는다.

### Step 4 — 중립 기본형 참조 세트 사양

참조 이미지 또는 Soul ID용 시드를 **중립 기본형**으로 설계한다. 사용자가 특정 장면이나 소품을 고정하려는 경우에는 그 목적을 별도로 적는다.

- 여러 장면에서 재사용할 참조에는 고정 외형·기본 의상·중립 포즈를 우선 넣는다. 손에 든 물건과 장면별 동작은 컷 프롬프트(`story-webtoon-art`)에서 지정한다.
- 참조의 소품이 이후 이미지에 반복될 수 있으므로, 실제 생성 결과를 보고 필요하면 참조를 조정한다.
- 각도 목록: 정면·측면·반측면·표정 변화. (비표준어 "반쯔렴"은 쓰지 않는다 → **반측면**.)
- 비슷한 두 인물은 구별할 요소를 정한다. 생성 결과에서 혼동이 계속되면 사용자와 앵커 변경을 정한 뒤 참조를 다시 만든다(`references/neutral-base-rule.md`).

### Step 4-생성 실행 — 현재 앱 도구 확인

ChatGPT Work에서는 현재 앱에 노출된 기본 이미지 도구를 먼저 확인한다. OpenAI가 Images 2.5를 제공한다고 안내하지만, 실제 호출의 모델 표시가 없으면 정확한 모델 사용을 단정하지 않는다. 사용자가 Higgsfield 이미지나 Soul ID 학습을 지정하면 현재 호스트의 Higgsfield 공식 연결에서 해당 도구·비용·권한·동의 절차를 확인한다. 이 스킬은 참조 사양과 일관성 앵커까지만 정한다.

Higgsfield 등 유료 외부 생성은 현재 비용을 사용자에게 알리고 명시적 승인을 받은 뒤에만 실행한다.

> 이미지 도구가 없으면 완성된 캐릭터 참조 프롬프트를 제공하고, 실제 이미지를 만들었다고 표시하지 않는다.

## 4. 출력 형식

```markdown
# [캐릭터 이름] 캐릭터 시트

## 서사 정보
- 성격 키워드 / 역할 / 말투 / 애착 포인트

## 비주얼 시트 ([인물 8항목 / 동물 8항목] — visual-sheet-tables 참조)
| 항목 | 내용 |
| ... |

## 일관성 앵커 (화마다 고정 · qc 판정 기준)
- [1~2가지 — 예: 은발 + 왼쪽 눈 밑 점]

## 중립 기본형 참조 세트 사양
- 각도: 정면·측면·반측면 / 표정 1~2개
- 소품·상황 포즈: 없음(컷 프롬프트에서 부여)
→ 이미지 생성은 현재 호스트의 기본 경로, 명시적 Higgsfield·Soul 요청은 해당 전용 경로
```

## 5. 주의사항

- **레귤러/게스트 2계층 예산을 지킨다.** 레귤러는 전체 시트, 게스트는 그 화 외형만 간략히(여러 화 일관성 부담 없음). 상세는 `references/visual-sheet-tables.md`.
- **일관성 앵커를 빼먹지 않는다.** 앵커 없는 시트는 qc가 판정할 기준이 없다.
- 여러 장면에 재사용할 참조는 중립 기본형을 우선 사용한다. 의도적으로 고정할 소품은 시트에 명시한다.
- **크레딧 수치를 지어내지 않는다.** Higgsfield 경로를 사용할 때만 실제 비용 조회값을 확인한다.

## 6. 관련 스킬

### Before
- `story-webtoon-planner` — 레귤러 인원과 서사 역할
- `story-series-bible` — 캐릭터 절에 앵커·시트를 기획서로 보관

### After
- `story-webtoon-art` — 컷 프롬프트에 캐릭터 참조·앵커 삽입
- `story-webtoon-qc` — 일관성 앵커 위반 판정

### 위임
- 현재 앱의 기본 이미지 도구 — 노출과 모델 표시를 확인한 뒤 생성
- 현재 호스트의 Higgsfield 공식 연결 — 사용자가 이미지를 명시한 경우
- 현재 호스트의 Higgsfield 공식 연결 — Soul ID·일관성 참조를 명시한 경우
