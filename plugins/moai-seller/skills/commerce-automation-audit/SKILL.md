# 커머스 자동화 진단

## 입력 확인

업무별 처리 건수, 한 건당 소요 시간, 예외율, 오류 처리 비용, 현재 도구, 담당자, 판매 채널을 확인한다. 이 중 빠진 값은 **미측정**으로 적고 효과 계산에서 제외한다. 고객 정보, 주문 정보, 가격을 바꾸는 권한은 현재 연결된 공식 연동과 판매자 계정 범위에서 확인한다.

## 진단

상품 운영, 가격·프로모션, 주문·정산, 재고·물류, 마케팅·고객, 데이터·경영의 업무를 각각 기록한다. 반복 업무라는 이유만으로 자동화하지 않는다. 입력 품질, 처리 규칙, 예외 사례, 되돌리기 방법을 먼저 확인한다.

| 항목 | 확인할 내용 |
|---|---|
| 현재 작업 | 시작 조건, 입력, 출력, 담당자, 처리 건수 |
| 데이터 | 누락·중복·시차, 개인정보 포함 여부 |
| 연동 | 해당 계정의 API·MCP 권한, 사용 제한, 장애 처리 |
| 예외 | 취소·환불·부분 배송·품절·중복 요청 |
| 승인 | 가격, 발송, 환불, 재고 조정의 책임자 |
| 결과 | 처리 시간, 오류, 재작업, 고객 영향 |

자체 클라이언트를 새로 설계하기 전에 서비스의 **공식 MCP**가 필요한 작업을 제공하는지 확인한다. 제공하지 않는 기능은 해당 공식 API의 권한과 약관을 확인한 뒤 별도 개발 범위를 제안한다. 크롤링이나 키 우회는 대체 연결 수단으로 제시하지 않는다.

## 우선순위

후보별로 월간 절감 시간은 `월간 건수 × (기존 처리 시간 − 자동화 후 검수 시간) − 예외 처리 시간`으로 계산한다. 금액은 실제 인건비·도구 사용료·구축비·유지비·오류 비용을 같은 기간으로 맞춰 산출한다. 값이 없으면 순위는 정성 판단으로 표시하고, 작은 파일럿에서 측정할 항목을 정한다. 특정 영역이 항상 가장 높은 ROI라고 가정하지 않는다.

## 실행 순서

1. **기준선 측정**: 같은 유형의 작업과 예외를 일정 기간 기록한다.
2. **작은 파일럿**: 한 업무를 고르고, 되돌릴 수 있는 범위에서 실행한다. 고객·가격·환불에 영향을 주는 쓰기 작업은 담당자가 승인한다.
3. **검증·확대**: 기준선과 파일럿의 처리 시간, 오류, 재작업, 고객 영향을 비교한다. 효과가 확인된 작업만 넓힌다.

재시도는 멱등성과 중복 처리를 확인한 작업에만 적용한다. 주문 생성·환불처럼 되돌릴 수 없는 결과는 실패했다고 무작정 재시도하지 않는다. 보존 기간이 정해진 감사 기록은 그 기간에 맞춰 남긴다.

## 출력

업무별 현황 표, 데이터·권한의 빈칸, 우선순위 근거, 파일럿 범위, 사람의 승인 지점, 성공·중단 기준을 낸다. 절감률·ROI·일정은 실제 자료나 명시된 가정으로 계산할 수 있을 때만 제시한다. 보고서 검수 도구가 연결돼 있지 않으면 자동 검수를 수행했다고 적지 않는다.
