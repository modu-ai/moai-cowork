# 커머스 시장조사

## 입력

상품 범위, 판매 채널, 가격대, 조사 기간, 판매 지역을 확인한다. 연결된 공식 데이터 도구가 제공하는 지표와 권한을 먼저 확인하고, 없으면 사용자가 제공한 내보내기 파일이나 공개 자료를 쓴다. 검색 추세 지수와 실제 검색량, 상품 노출 수와 매출을 혼동하지 않는다.

네이버 Search Trend·Shopping Insight API는 제공 창구가 바뀔 수 있다. [네이버 개발자 공지](https://developers.naver.com/notice/article/32530)에 따라 사용 시점의 NAVER API HUB와 각 서비스 문서를 확인한다. 기존 개발자센터 키나 종료된 쇼핑 검색 API가 계속 통한다고 가정하지 않는다.

## 조사

| 축 | 확인할 자료 | 해석할 때 주의할 점 |
|---|---|---|
| 시장 | 공공 통계, 업계 보고서, 판매자 실측 | 범위·기간·단위·표본 |
| 경쟁 | 실제 판매 페이지의 가격·구성·후기 | 노출 순위가 매출 순위는 아님 |
| 검색 | 도구의 추세 지수·키워드 자료 | 상대 지수와 절대 검색량을 분리 |

자료마다 URL 또는 파일, 조회일, 적용 지역, 기간을 기록한다. 지표를 비교할 때 기준을 맞춘다. 자료가 없는 축은 **미확인**으로 남기고 추가 조사 방법을 적는다. 경쟁사의 ROAS·CTR·매출은 공개되지 않았다면 추정 수치로 채우지 않는다.

## 판단

고객이 실제로 겪는 문제, 경쟁 상품과의 차이, 가격·수수료·배송비를 감안한 공헌이익을 함께 본다. 포지셔닝은 품질, 가격, 전문성, 편의, 가치관 중 고객 근거가 있는 축으로 제안한다. 새 카테고리 명칭을 만들었다는 이유만으로 독점 지위나 높은 마진을 기대하지 않는다.

## 출력

1. 조사 범위와 자료 목록
2. 확인된 수치와 단위, 기간
3. 경쟁 상품 비교
4. 검색 추세와 그 한계
5. 진입 가설, 반대 근거, 검증할 항목

수치를 얻지 못하면 빈칸을 유지한다. 결론은 확인된 자료의 범위를 넘지 않게 적고, 후속 고객 조사에는 `commerce-jtbd-persona`를 사용할 수 있다.
