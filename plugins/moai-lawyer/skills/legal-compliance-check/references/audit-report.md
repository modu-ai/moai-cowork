# 내부 감사 보고서 작성

감사의 의뢰 주체, 조사 대상과 기간, 접근 권한, 적용 기준을 먼저 기록한다. 자료를 받지 않은 현장 방문·직원 인터뷰·시스템 로그 확인은 수행했다고 쓰지 않는다.

1. 기준표를 만든다: 공식 법령·고시 또는 내부 정책의 버전, 적용 요건, 확인할 증거.
2. 실제 받은 자료의 파일·날짜·소유자를 적는다. 진술과 문서, 운영 로그를 구분한다.
3. 각 항목을 `확인 범위에서 충족`·`불일치`·`미확인`·`비적용`으로 표시하고 근거를 붙인다. 표본만 보았다면 모집단 전체로 일반화하지 않는다.
4. 시정안에는 조치 담당자와 확인 방법을 제안하되, 법정 기한은 원문에서 확인한 경우에만 적는다.
5. 의뢰인이 요청한 범위에서 보고서 초안을 작성한다. 배포·서명·외부 보증 상태는 실제 기록으로만 보고한다.

보고서에는 범위, 기준 날짜, 수집 방법, 증거 목록, 발견 사항, 한계와 후속 확인 항목을 포함한다. 자료 접근이 거부되면 그 공백을 기록한다. 별도 에이전트 팀이나 `_workspace/` 폴더를 무조건 만들 필요는 없다.
