# IP 선행조사 보고서 (상표·특허, 국내외)

## 개요

공식 IP 데이터베이스로 조사하고, 조사 시점에 다시 따라 할 수 있는 검색 로그와 위험 평가·출원 전략·한계를 담은 보고서를 만듭니다. `moai-mcp-ip`가 현재 호스트에 연결돼 있으면 그 도구를 사용합니다. 연결되지 않았으면 접근 가능한 공식 기관 검색 화면으로 조사하고, 사용한 경로와 한계를 국가·권리별로 적습니다.

**결과 0건은 "등록 가능"이나 "침해 없음"의 근거가 아닙니다.** 이 스킬의 산출물은 예비조사이며 변리사·변호사의 법률 의견을 대신하지 않습니다.

**면책 고지: AI 보조 조사이며 전문 법률 자문을 대체하지 않습니다**

## 트리거 키워드

상표 선행조사, 상표 등록 가능성, 브랜드명 조사, 해외 상표, 특허 선행기술, 해외 특허 조사, 특허 패밀리, 권리상태, FTO 예비조사, KIPRIS, USPTO, JPO, EPO, 특허 API 키 발급

## 1단계 — 범위를 먼저 정한다

사용자가 이미 구체적으로 말한 것은 다시 묻지 않습니다. 결과를 바꾸는 정보만 현재 호스트의 질문 채널로 확인합니다. 질문 채널이 없다면 누락된 입력을 표시하고 가능한 범위부터 진행합니다.

- **권리**: 상표, 특허·실용신안, 둘 다
- **국가·지역**과 조사 기준일
- **상표**: 정확한 표장, 띄어쓰기·대소문자 변형, 음역(한글·영문·가타카나), 실제 판매할 상품·서비스, 로고 사용 여부
- **특허**: 제품·기술의 필수 구성, 해결하려는 과제, 예상 IPC/CPC, 기준일, 경쟁사
- **목적**: 출원 가능성, 네이밍 채택, 선행기술, 동향, 무효자료, FTO 예비조사
- **산출물**: 대화 요약 또는 DOCX·PDF 정식 보고서

FTO·무효·침해·등록 가능성은 법률 의견이 필요한 고위험 영역입니다. 조사 목적과 판단의 한계를 보고서 맨 앞에 밝힙니다.

## 2단계 — 사용 가능한 공식 검색 경로 확인

### 소스 고르기

| 국가 | 상표 | 특허 |
|---|---|---|
| 한국 | `kipris-plus` — 검색·상세 모두 API | `kipris-plus` — 검색·상세 모두 API |
| 미국 | 후보 발굴: API 없음 → USPTO Trademark Search 웹 화면 / 상태 확인: `uspto-tsdr` | `uspto-odp` — 검색·메타데이터 |
| 일본 | 후보 발굴: API 없음 → J-PlatPat 웹 화면 / 번호 확인: `jpo` | 후보 발굴: J-PlatPat 또는 `epo-ops`(JP 공개문헌) / 번호 확인: `jpo` |
| 유럽·국제 | 무료 API 없음 → EUIPO·WIPO 웹 화면 | `epo-ops` — 검색·서지·패밀리·법적상태 |

### 규칙

1. 현재 연결에 `moai-mcp-ip`가 실제로 보이면 조사에 쓸 소스를 정하고 `ip_check_access(sources=[...])`를 부릅니다. 도구가 보이지 않으면 API를 호출했다고 쓰지 않고 공식 기관 웹 화면의 검색 범위로 진행합니다.
2. `missing`이 있으면 그 API는 호출하지 않습니다. 공식 등록 절차를 안내하고, 동시에 접근 가능한 공식 공개 검색 화면에서 조사할 수 있습니다. 웹 조사의 범위를 결과에 표시합니다.
3. **키 값을 채팅으로 받지 않습니다.** 실제 연결 가능한 호스트 설정 화면을 확인합니다. 자체 서버가 로컬에서 실행되는 경우 자격증명 파일은 macOS·Linux `~/.moai/mcp/ip.json`, Windows `C:\Users\<사용자>\.moai\mcp\ip.json`입니다. 사용자가 채팅에 키를 붙여 넣었다면 그 값을 파일·보고서·로그에 옮기지 않고 재발급 필요성을 안내합니다.
4. 사용자가 "설정 완료"라고 하면 `ip_check_access(verify=true)`로 **값을 보여 주지 않은 채** 연결만 확인합니다. `auth_error`(키 오류·상품 기간 만료)와 검색 결과 0건은 다른 것입니다. KIPRIS는 특허 상품과 상표 상품의 이용 기간이 따로라 둘을 따로 보고합니다.
5. API 사용 여부와 웹 화면 사용 여부를 증거대장에 따로 적습니다. 연결이나 인증이 없어 공식 웹 화면만 썼다면 그 범위를 축소해 보고합니다. 키 등록을 조사 시작의 보편적인 전제 조건으로 만들지 않습니다.
6. 미국 상표 문자 검색과 일본 키워드 검색 등 현재 서버가 제공하지 않는 검색은 공식 웹 화면에서 확인합니다. 특정 기관의 API 제공 여부는 현재 공식 안내로 재확인합니다.

누락 시 답변 순서는 `references/api-access.md` §누락 안내 템플릿을 따릅니다.

## 3단계 — 조사 계획

게이트를 통과하면 검색 전에 조사식 표를 만듭니다. 조사식마다 목적·소스·도구·검색 필드·분류·상태·기간·언어/음역을 적습니다.

- 상표: `references/trademark-workflow.md`
- 특허: `references/patent-workflow.md`
- 둘 다 조사하면 검색대장을 나누고, 보고서에서 연결 관계만 종합합니다.

### 도구 대응표

| 하려는 일 | 도구 |
|---|---|
| 한국 상표 후보 찾기 | `kipris_trademark_search` (표장명·`similarity_code`·`classification`·`statuses`) |
| 한국 상표 행정 이력·지정상품 | `kipris_trademark_detail` |
| 한국 특허 검색 | `kipris_patent_search` (`word`·`claim`·`ipc_number`·`applicant`·`status`) |
| 한국 특허 서지 | `kipris_patent_detail` |
| 미국 특허 검색 | `uspto_patent_search` (`q`·`filters`·`range_filters`) |
| 미국 특허 출원 정보 | `uspto_patent_application` |
| 미국 상표 상태·소유자·지정상품 | `uspto_trademark_status` (웹에서 찾은 일련번호로) |
| 일본 특허·상표 경과·등록 | `jpo_patent_progress` · `jpo_patent_registration` · `jpo_trademark_progress` · `jpo_trademark_registration` |
| 일본 번호 변환·출원인 코드 | `jpo_case_number_reference` · `jpo_applicant_lookup` |
| 유럽·국제 특허 검색 | `epo_search` (CQL) |
| 패밀리·법적 상태 | `epo_family` (`constituent="legal"`) · `epo_legal` · `epo_biblio` |

## 4단계 — 증거를 남기며 실행

모든 검색을 증거대장에 한 줄씩 남깁니다. 같은 검색을 다시 했으면 덮어쓰지 않고 새 줄을 추가합니다.

| 필드 | 내용 |
|---|---|
| timestamp | 시간대 포함 검색 시각 |
| jurisdiction | 국가·지역 |
| source / tool | 소스 ID와 도구 이름, 또는 웹 화면 이름 |
| query | 실제로 넘긴 인자 원문 |
| filters | 분류·유사군·상태·기간·출원인 |
| result_count | 도구의 `total_count`(전체 건수) |
| reviewed_count | 실제로 열람한 건수 |
| key_records | 번호·표장/명칭·권리자·상태·관련성 |
| evidence | 사건 공식 링크 또는 응답 식별자 |
| limitation | 반영 지연·페이지 한도·일일 한도·웹 화면 한계·잘린 응답(`truncated`) |

- 관찰과 해석을 나눕니다. "완전일치 0건"은 관찰일 뿐이며, 이것만으로 등록 가능성·출원 실익·충돌 위험·비침해 여부를 올리거나 내리지 않습니다. 0건 뒤에는 검색 범위, 변형·음역·유사군·인접 상품, 미등록 사용, 미공개 출원, 데이터 반영 지연을 반드시 함께 적습니다.
- `total_count`와 `returned_count`가 다르면 전수 검토라고 쓰지 않습니다.
- 도구가 `setup_required`·`auth_error`·`quota_exhausted`·`rate_limited`를 돌려주면 조사 결과가 아닙니다. 해당 소스를 미조사로 기록합니다.

## 5단계 — 위험 평가

### 상표
- 표장 유사: 외관·호칭·관념·전체 인상, 식별력이 강한 부분과 약한 부분
- 상품·서비스 관련성: 성질·용도·수요자·유통경로, 유사군 코드
- 절대적 거절: 보통명칭, 성질 표시, 식별력 부족, 오인·혼동
- 상대적 거절: 존속 선행권리, 계류 출원, 저명표장, 동의·공존 가능성
- 사용 위험: 미등록 사용, 회사명·도메인·앱스토어·SNS·마켓플레이스
- 국가별 절차: 선출원주의, 사용 의사·사용 증거, 대리인 요건, 우선권, 불사용 취소

### 특허
- 관련성은 초록보다 독립청구항을 우선합니다.
- 신규성은 한 문헌이 필수 구성을 모두 공개했는지를 봅니다.
- 진보성은 여러 문헌의 결합 가능성과 결합 동기를 나눠 봅니다.
- 패밀리·우선일·법적 상태·존속기간·등록국을 확인합니다.
- FTO는 유효한 청구항의 모든 구성요소가 대응되는지 보는 별도 분석입니다. 키워드 검색이나 유사 특허 목록만으로 FTO를 끝냈다고 하지 않습니다.

위험 등급을 요청받았다면 확인한 권리·상품·청구항과 미조사 범위에 근거해 설명합니다. 자료가 부족하면 등급 대신 `판단 불충분`을 씁니다. 근거 없는 확률 숫자는 만들지 않습니다.

## 6단계 — 출원·보호 전략

조사 목적 범위 안에서만 제시합니다.

- **상표**: 문자·음역·로고의 출원 순서, 핵심 류와 조건부 류, 지정상품 문안, 개별국 출원과 마드리드 비교, 파리 우선권 마감, 사용 증거 관리
- **특허**: 국내 우선 출원, PCT·파리 루트, 청구항 차별화 방향, 공개 전 비밀 유지, 추가 실험·도면·발명자 자료, 회피 설계 검토
- 출원인·권리자, 양도 계약, 직무발명, OEM·디자이너 권리 귀속이 불분명하면 확인 필요 항목에 올립니다.
- 요청받지 않은 실제 출원·결제·대리인 선임·메시지 발송은 하지 않습니다.

## 7단계 — 보고서

`references/report-schema.md` 구조를 따릅니다. 최소 구성:

1. 한 페이지 결론과 지금 내려야 할 결정
2. 조사 범위·기준일·소스·API와 웹 화면 사용 여부 및 미조사 범위(국가·권리별 표시)
3. 등록 가능성 또는 특허 관련성 매트릭스
4. 국가별 검색식·결과·핵심 사건
5. 절대적·상대적 위험과 대응 논리
6. 권리 포트폴리오와 출원 순서
7. 우선권·대리인·사용 증거·유지관리 일정
8. 증거대장
9. 공식 출처
10. 확인 필요 항목과 면책

정식 보고서가 필요하면 `moai-officer:doc-docx`(편집용)와 `moai-officer:doc-pdf`(검토용)로 만들고, 표 잘림·링크·글꼴을 렌더링으로 확인합니다. 원본 증거대장은 Markdown·CSV·JSON 중 하나로 함께 보관합니다.

한국어 보고서는 전달 전에 `moai-coworker:ai-slop-reviewer` → `moai-writer:korean-humanize` 순서로 검수합니다. 청구항·미공개 기술·계약·원가 같은 민감 정보가 있으면 외부 맞춤법 서비스로 보내지 않습니다.

## 완료 기준

- 조사에 쓴 소스와 인증 여부를 실제 연결 결과대로 기록했다. 공식 웹 화면만 썼다면 그 한계와 미조사 범위를 표시했다.
- 상표는 정확 표장·변형·음역·구성요소, 특허는 키워드·분류·청구항 검색이 목적에 맞게 수행됐다.
- 존속·소멸·계류 상태와 상품·서비스 또는 청구항 관련성을 구분했다.
- 조사식·전체 건수·검토 건수·사건 번호·공식 출처·한계를 기록했다.
- 관찰과 법적·사업적 해석을 나눴다.
- "등록 보장", "침해 없음", "FTO 완료"처럼 검증 범위를 넘는 표현이 없고, "출원 실익이 높다"·"등록 전망이 유리하다"·"충돌 위험이 사실상 없다"처럼 같은 뜻을 돌려 말한 결론도 없다. 긍정적 등록 전망은 절대적 거절 사유·유사 표장·지정상품 관련성·권리상태·실제 사용 위험을 모두 검토한 뒤에만 쓰고, 특허에서 0건이면 FTO·비침해 등급을 내리지 않고 `판단 불충분`으로 둔다.
- 실행 우선순위와 확인 필요 항목이 있다.
