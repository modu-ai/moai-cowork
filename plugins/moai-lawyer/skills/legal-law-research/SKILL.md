# 법령 리서치

법률 자문이 아닌 참고 자료다. 법령의 존재, 사건 날짜에 적용되는 판본, 판례의 내용과 이후 변경 여부를 각각 확인한다.

## 조회 경로

1. 현재 호스트에서 `korean-law` MCP의 실제 도구 목록과 연결 상태를 확인한다. 보이면 사용 가능한 `search_law`, `get_law_text`, `legal_analysis` 등의 현재 스키마를 읽고 필요한 도구만 호출한다. 과거 문서의 도구 수·매개변수를 현재 계약으로 단정하지 않는다.
2. 도구가 없거나 인증되지 않았다면 [국가법령정보센터](https://www.law.go.kr/)와 해당 주무 기관의 공식 웹페이지를 직접 조회한다. MCP가 없다는 이유로 법령 조사를 포기하지 않는다. 웹 조사와 MCP 검증은 보고서에 구분해 쓴다.
3. [법제처 Open API 안내](https://open.law.go.kr/LSO/openApi/guideResult.do)는 OC 인증값을 요구한다. 키가 필요하면 공식 신청 경로를 안내하고 앱의 검증된 보안 설정 방법을 사용한다. **키를 채팅에 입력받거나 작업 파일·보고서·URL 예시에 실제 값으로 기록하지 않는다.** Codex는 Claude `user_config`를 자동 치환하지 않으므로 연결 방식을 확인하지 않은 채 성공을 약속하지 않는다. TLS 인증서 오류가 나도 검증을 끄거나 HTTP로 낮추지 않는다.

## 확인 순서

- 법령명, 조·항·호, 시행일, 사건 발생일과 관할을 정한다. 현행법과 과거 법령을 혼동하지 않는다.
- 원문 조항과 부칙·경과규정, 관련 시행령·고시를 확인한다. 도구의 `applicable_law` 결과가 있더라도 원문과 적용 사실을 대조한다.
- 판례는 사건번호·법원·선고일·판시 내용을 공식 기록으로 확인한다. `cite_check`가 있으면 후속 인용을 조사하되, 결과 하나만으로 판례가 법적으로 `살아 있다`고 단정하지 않는다.
- 문서 속 인용은 `verify_citations`가 있으면 보조 검사를 하고, 모든 인용의 원문 링크를 개별 대조한다. 도구가 실패하거나 링크가 열리지 않으면 검증 공백으로 적는다.
- 법령 개정 비교는 서로 다른 시행 판본의 실제 조문을 대조해 바뀐 문구를 인용 범위 내에서 요약한다.

## 출력

| 주장·인용 | 공식 원문 URL | 판본·날짜 | 확인한 내용 | 해석·한계 |
|---|---|---|---|---|
| 조문 또는 판례 | 직접 연결 | 시행일·선고일 | 원문으로 확인한 사실 | 사건 적용은 별도 판단 |

질문의 결론을 내기 위한 사실이 없으면 필요한 사실을 적고 조건부로 설명한다. 법령 본문과 판례, 학설·행정해석, 자신의 추론을 구분한다. 변호사 검토가 필요한 쟁점과 실제 조회하지 못한 출처를 명시한다.
