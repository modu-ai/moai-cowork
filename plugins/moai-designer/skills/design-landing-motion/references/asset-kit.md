# asset-kit.md — 랜딩 비주얼 킷

> `design-landing-motion` | 필요한 자산을 고르는 구성표. 생성은 현재 사용 가능한 이미지·영상 도구의 계약을 따른다.

**Evidence tier:** 2차 (Higgsfield 공식 스킬 `higgsfield-websites` v0.12.0, MIT — `asset-system.md` 착안. CLI 명령 계층은 제거하고 킷 구성과 규칙만 남김)

---

## 0. 왜 생성하는가

비주얼은 브리프와 브랜드를 뒷받침해야 한다. 기존 자산, 사용권이 확인된 이미지, CSS 표현, 생성 이미지를 목적에 맞게 고른다.

생성이 필요한 경우에는 한 브리프에서 톤과 사용처가 맞는 자산을 준비한다.

---

## 1. 사용자 자산이 언제나 이긴다

로고·브랜드 마크·제품 사진·팀 사진·폰트·기존 아이콘셋 — 사용자가 준 것은 **그대로 쓴다.** 대체품을 생성하지 않는다. 생성은 **빈 곳만** 채운다.

한 가지 예외: 사용자의 사진이 정한 방향과 심하게 부딪히면, 그들 사진의 **재그레이딩**을 제안한다. 진짜 제품·진짜 팀을 생성된 낯선 사람으로 바꾸지 않는다.

---

## 2. 킷 구성표

확인된 팔레트가 있으면 프롬프트에 명시하고, 스파인 모티프를 넣는다. 본문 카피는 HTML로 얹고, 사용자가 제공하지 않은 로고·워터마크는 생성하지 않는다.

| # | 항목 | 내용 | 필수 |
|---|---|---|---|
| 1 | **히어로 비주얼** | 브리프가 요구하는 중심 이미지. B2 효과를 쓸 때만 같은 구도의 어둡게/밝게 쌍을 준비 | 조건부 |
| 2 | **섹션 플레이트** | 필요한 배경 텍스처·분위기판 | 조건부 |
| 3 | **콘텐츠 이미지** | 확인된 제품·인물·화면 자료 또는 명시적으로 가상임을 밝힌 예시 | 섹션에 따라 |
| 4 | **커스텀 아이콘셋** | 아이콘 폰트를 기본값으로 쓰지 않는다. 한 벌로 6~12개를 같은 획 굵기·같은 모서리 언어로 생성하고 누끼 처리 | 권장 |
| 5 | **로고·모노그램** | 사용자에게 로고가 **없을 때만** | 조건부 |
| 6 | **OG 이미지** | 공유 카드가 필요하면 프로젝트의 대상 플랫폼 규격에 맞춰 준비 | 조건부 |
| 7 | **파비콘 세트** | 사이트에 필요하면 승인된 로고에서 파생 | 조건부 |
| 8 | **스크럽용 영상** | A계열 효과를 고른 경우만. 승인된 히어로 스틸에서 출발해 시작≠끝인 5초 클립 | 조건부 |

**아이콘 예외:** 폼·표처럼 작은 글리프가 20개 넘게 촘촘히 필요한 기능성 UI는 라이브러리 아이콘이 낫다. 다만 **한 시각 영역에서 두 세트를 섞지 않는다.**

---

## 3. 위임 방법

필요한 항목마다 프롬프트를 조립한다. 현재 앱과 이 플러그인에 실제 연결된 도구의 모델·출력 형식·비용·승인 절차를 확인한다. 별도 설치된 `moai-media` 스킬은 상세 절차로 활용할 수 있다.

| 필요한 것 | 확인할 경로 |
|---|---|
| 이미지 (ChatGPT Work 기본) | 현재 대화의 이미지 생성 도구 |
| 이미지 (Higgsfield 명시 선택) | 이 플러그인의 공식 Higgsfield 연결에서 이미지 생성 도구 확인 |
| 스크럽용 영상 | 공식 Higgsfield 연결에서 영상 생성 지원 여부 확인 |
| 누끼·업스케일·아웃페인팅 | 현재 연결에서 해당 편집 도구 지원 여부 확인 |
| GLB (B3 효과) | 현재 연결에서 실제 GLB 출력·변환 도구 지원 여부 확인 |
| 인물·마스코트 일관성 | 현재 연결에서 참조 이미지·일관성 기능 지원 여부 확인 |

도구가 없는 항목은 기존 자산이나 CSS 표현으로 대체할 수 있는지 확인하고, 생성이 꼭 필요하면 미완료로 기록한다. 외부 생성 경로를 쓴다면 항목 수와 해당 서비스의 실제 비용 조건을 확인한다.

---

## 4. 파일 배치

- 프로젝트가 파일을 받을 수 있으면 정적 자산 디렉터리에 저장한다. 외부 URL을 쓸 때는 사용권·만료·캐시 정책을 확인한다.
- 크기: 히어로 ≤2K, 컷아웃 ~800px, 아이콘 ~256px. 필요 이상으로 큰 이미지는 LCP를 망친다.
- **채택되지 않은 후보는 공개 디렉터리에서 뺀다.** 히어로 후보 2장 중 1장만 남긴다. 쓰이지 않는 파일이 배포물에 섞이면 용량과 혼선을 부른다.
- 모든 내려받은 파일은 실제로 어딘가에서 참조돼야 한다 → `quality-gate.md`.

---

## 5. 규칙과 함정

- **일관성 점검은 한 번에 모아서.** 킷이 도착하면 전부 **한 번에 같이** 본다. 한 장씩 따로 보면 서로 어긋난 걸 못 잡는다. 그레이딩이 튀는 항목만 팔레트 hex를 더 강하게 박아 재생성한다.
- **그레이딩이 섞인 킷은 에셋이 아예 없는 것보다 싸구려로 보인다.** 이게 한 번에 모아 보는 이유다.
- **여러 장 요청이 격자 한 장으로 올 수 있다.** 배치 파라미터가 2×2 시트를 반환하기도 한다. 슬롯에 물리기 전에 실제로 뭐가 왔는지 확인한다 — N개 요청이 N개 파일을 뜻하지 않는다.
- **아이콘 시트를 잘랐으면 누끼를 돌린다.** 자른 조각은 시트 배경을 그대로 물고 있어 페이지 배경과 싸운다.
- 생성 실패 시 원인과 실제 재시도 가능 여부를 확인한다. 다른 자산으로 바꾸면 그 출처와 변경 이유를 보고한다.
- 흑백 방향이면 프롬프트에도 내보내기에도 흑백을 강제한다.
- 인물 이미지는 지역에 맞고 그럴듯해야 한다. 워터마크 박힌 stock 얼굴을 쓰지 않는다.
