# design-sync-upload — 디자인 시스템 자료 전달

이 스킬은 사용자가 고른 디자인 시스템 자료를 정리하고 실제 전달 상태를 보고한다. 파일을 준비한 것과 Claude 계정에 업로드한 것, 디자인 시스템으로 분석한 것, 팀에 게시한 것은 서로 다른 단계다.

## 1. 자료와 권한 확인

1. 사용자가 제공한 브랜드 가이드·코드베이스·완성 화면·토큰·로고 중 필요한 것만 목록으로 만든다. `DESIGN.md`나 DTCG·CSS·shadcn 세 층은 **있을 때만** 포함한다. 없는 파일이나 로고 변형을 만들지 않는다.
2. 각 파일의 위치·크기·형식을 확인한다. 고객 자료·내부 수치·폰트 파일·저작권 자산은 업로드 범위와 사용권을 확인한다. 필요한 부분만 복사하거나 민감 정보를 가린 사본을 만들되 원본은 보존한다.
3. 사용자에게 대상 Claude 계정·조직과 전달 파일 목록을 보여준다. 조직 공용 시스템 덮어쓰기·삭제·게시가 필요한 경우 실제 대상과 변경 내용을 확인하고 해당 동의를 받는다.

## 2. 현재 환경에 맞는 경로

| 현재 환경 | 진행 |
|---|---|
| Claude Cowork 또는 Claude 대화 | 사용자가 선택한 파일을 현재 대화에 첨부할 수 있으면 첨부하고, 디자인 시스템 생성·수정 요청을 전달한다. 앱이 제공하는 디자인 시스템 화면에서 실제 결과를 확인한다. |
| ChatGPT Work | 파일 묶음과 짧은 `UPLOAD-GUIDE.md`를 준비한다. 사용자가 Claude 앱의 디자인 시스템 화면에서 직접 첨부한다. ChatGPT 안에서 Claude 업로드가 끝난 것으로 보고하지 않는다. |
| Claude Code | 사용자가 해당 환경을 쓰는 경우 공식 `/design-sync` 경로를 안내한다. 이 명령을 데스크톱 앱의 일반 슬래시 명령처럼 안내하지 않는다. |
| DesignSync 도구가 현재 세션에 실제로 노출됨 | 도구의 현재 스키마·인증·대상 권한을 먼저 읽는다. 확인된 읽기 메서드로 대상과 기존 파일을 살핀 뒤 쓰기 계획을 만든다. 예전 `finalize_plan`·`write_files`·`register_assets` 계약을 확인 없이 호출하지 않는다. |

도구가 없거나 인증되지 않았으면 파일 준비와 UI 안내까지 진행한다. 인증 실패를 업로드 성공으로 바꾸지 않는다. 업로드 UI의 이름과 클릭 경로가 계정·제품 버전에 따라 다르면 현재 보이는 화면을 따른다.

## 3. 파일 묶음

사용자가 접근할 수 있는 프로젝트 안에 `design-sync-staging/` 같은 상대경로 폴더를 만든다. 승인된 파일만 복사하고 다음 안내를 함께 둔다. 디렉터리를 만들 수 없는 대화에서는 파일 목록과 업로드 순서를 채팅에 적는다.

```markdown
# 디자인 시스템 자료 전달 안내

- 대상 계정·조직: [확인된 값]
- 자료: [실제 준비한 파일과 용도]
- 제외한 자료: [민감 정보·사용권 미확인 등]
- 전달 경로: Claude Design의 현재 디자인 시스템 화면에서 파일 첨부
- 전달 후 확인: 추출된 색·서체·컴포넌트가 원본과 맞는지 실제 결과로 점검
- 팀에 게시: 조직 권한과 결과 검토 후 별도 결정
```

Claude의 [디자인 시스템 설정 안내](https://support.claude.com/en/articles/14604397-set-up-your-design-system-in-claude-design)에 따르면 대화의 업로드 파일·연결 앱·Figma·코드베이스를 자료로 사용할 수 있고, 별도 Claude Design 화면에서는 조직 설정에서 자산을 올릴 수 있다. 완성된 화면이나 덱처럼 실제 사용 예를 함께 주면 추출 결과를 검토하기 쉽다. 파일을 업로드했다고 색·컴포넌트 추출이 정확해졌다고 단정하지 않는다.

## 4. 자동 쓰기 도구가 실제로 있을 때

- 기존 파일을 덮어쓰거나 삭제한다면 대상 프로젝트·경로·신규/덮어쓰기/삭제 목록·현재 내용을 잃을 수 있는 범위를 사용자에게 보여준다. 삭제는 쓰기와 따로 선택할 수 있게 한다.
- 현재 스키마가 제공하는 계획·승인 절차를 따른다. 파일 해시를 승인 직전과 호출 직전에 비교할 수 있으면 비교한다. 도구가 파일을 다시 읽는다면 그 사이 변경을 완전히 막았다고 보증하지 않는다.
- 쓰기 응답이 모호하면 원격 상태를 다시 읽어 어떤 파일이 기록됐는지 확인한다. 확인 없이 같은 쓰기를 재시도하지 않는다. 일부만 올라갔으면 부분 성공과 남은 파일을 구분한다.
- 게시나 조직 기본값 변경은 업로드와 별개로 다룬다. 화면 검토와 해당 권한·사용자 의사가 확인된 경우에만 실행한다.

```text
전달: [실제 업로드 성공 | 일부 성공 | UI 전달 대기 | 미실행]
추출 검토: [실제로 확인한 색·서체·컴포넌트 | 미검증]
게시: [실제 게시 확인 | 미게시 | 미검증]
남은 일: [사용자가 수행할 단계 또는 재검토 항목]
```
