# 브랜드 카피 작성

브랜드 보이스, 대상 사용자, 화면 목적과 실제 제품 기능을 확인해 문구를 쓴다. MoAI 프로젝트에 `.moai/project/brand/brand-voice.md`가 있으면 읽고 그 용어와 문체를 따른다. 데스크톱 앱에서 그 파일이 없으면 사용자가 제공한 브랜드 자료를 사용한다. 자료가 없으면 임시 문체를 제안값으로 표시하고 브랜드 확정 카피라고 부르지 않는다.

## 진행 방법

1. 필요한 화면과 각 문구의 역할을 정한다. 히어로·기능·가격·후기·푸터를 모든 페이지에 강제하지 않는다.
2. 실제로 제공하는 기능, 적용 대상, 조건과 제약을 자료에서 확인한다. 수치, 무료 체험, 환불, SLA, 고객사 이름, 후기, 경쟁 우위를 만들어내지 않는다.
3. 제목은 사용자가 얻는 결과나 해결할 작업을 구체적으로 쓰고, 버튼은 누른 뒤 일어나는 동작을 분명히 쓴다. 오류 메시지에는 문제와 사용자가 취할 수 있는 다음 행동을 담는다.
4. 브랜드가 쓰는 언어와 호칭을 유지한다. 상투어와 근거 없는 최상급 표현을 점검하되, 실제 브랜드 서체·표현을 일괄 금지하지 않는다.
5. 대안 문구는 비교가 유용할 때만 만든다. 변형을 만들었다는 이유로 A/B 테스트를 수행하거나 전환율이 높다고 주장하지 않는다.
6. 최종 문구의 사실·숫자·링크·법적 문구를 원자료와 대조한다. 미확인 항목은 공개용 문구에 넣지 않고 확인 과제로 남긴다.

## 산출물

MoAI 코드 기반 디자인 파이프라인이 섹션 JSON을 기대하면 `page_type`, `sections`, `metadata` 구조로 출력하고 실제 필요한 섹션만 포함한다. 각 섹션의 `primary`는 기본 문구이며 `variant_a`는 실제 대안이 있을 때만 쓴다. 일반 데스크톱 요청은 표나 문서처럼 사용자가 편집하기 쉬운 형식으로 낸다. 자동 계산하지 않은 읽기 수준이나 성과 점수를 메타데이터에 채우지 않는다.

카피 길이는 실제 레이아웃과 언어에 맞춰 조정한다. 영어의 단어 수나 Flesch-Kincaid 점수를 한국어 카피에 적용하지 않는다. 디자인 토큰과 레이아웃을 함께 만드는 경우 `moai-designer:design-brand-system`에 문구 길이와 계층을 전달한다. 문체 검수에는 `moai-coworker:ai-slop-reviewer` 또는 `moai-writer:korean-humanize`를 사용할 수 있지만 사실·의미·숫자는 보존한다.
