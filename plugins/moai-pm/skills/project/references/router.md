# project 스킬 라우팅

사용자의 요청을 산출물과 작업 단계로 해석하고, 현재 설치·노출된 스킬 중 적합한 체인을 고른다. 키워드만으로 역할이나 위험도를 확정하지 않는다.

## 인벤토리와 진입

1. 기존 프로젝트라면 `AGENTS.md`의 워크플로우에서 해당 산출물의 체인을 찾는다.
2. 새 체인이 필요하면 배포 로스터 정본 `.claude-plugin/marketplace.json`과 현재 런타임에 노출된 스킬을 대조한다. 설치 경로만 보고 사용 가능하다고 가정하지 않는다.
3. 사용자 요청의 산출물·독자·도메인·채널·자료 형식을 뽑고, 실제 스킬 설명과 입력·출력을 읽어 후보를 좁힌다.
4. 후보가 여러 개면 산출물의 최종 형태를 만드는 스킬을 중심으로 정한다. 복합 요청이면 필요한 스킬을 순서대로 연결한다.
5. 적합한 스킬이 노출되지 않으면 누락 사실을 알려 설치 안내 또는 현재 가능한 범위를 제시한다. 없는 스킬을 호출했다고 기록하지 않는다.

예를 들어 카드뉴스는 콘텐츠 제작 스킬, 브랜드 시스템은 디자인 스킬, 제품 상세페이지는 커머스 스킬의 실제 설치 여부와 기능을 확인해 라우팅한다. 이 예시는 고정 플러그인 로스터가 아니다.

`/project update`, `/project evolve`, `/project doctor`는 PM 허브의 관리 요청이다. 데스크톱 앱에서 명령이 보이지 않으면 자연어로 같은 작업을 요청할 수 있다.

## 모호한 요청

산출물 유형이 분명하면 그 유형에 맞는 체인을 우선한다. 둘 이상의 최종 산출물이나 목표가 서로 다르면 사용자에게 선택을 요청한다. Claude에서는 현재 제공되는 질문 도구, ChatGPT Work에서는 현재 세션에 노출된 `request_user_input` 또는 `request_user_input_async`의 실제 스키마를 따른다. 질문 도구가 없으면 필요한 결정을 명시한다. 선택지의 최대 개수와 필드 형식을 다른 런타임에서 가져오지 않는다.

## 복합 요청

하나의 `AGENTS.md` 워크플로우에 산출물별 체인을 기록한다. 예를 들어 사업계획서와 브랜드 디자인을 함께 요청하면 두 산출물의 입력·담당 스킬·검수 방법을 각각 적고 필요한 공유 자료만 연결한다. 커스텀 에이전트가 필요한 반복 작업이라면 두 데스크톱 호스트에서 사용할 수 있는 대응 파일을 생성한다. 에이전트 기능이 노출되지 않은 환경에서도 체인을 순서대로 실행할 수 있어야 한다.

개발 환경 설정까지 요청받으면 비개발 범위와 개발 범위를 구분하고, 현재 플러그인이 다룰 수 있는 부분을 먼저 처리한다.

## 검증 깊이

법률·계약·개인정보·세무·재무·의료·규제 또는 외부 발송처럼 정확성의 대가가 큰 작업은 `DEEP`으로 분류해 원출처와 실제 결과를 확인한다. 복합 체인도 각 산출물의 위험도를 따로 평가한다. 일반 문서·카피는 `NORMAL`, 단순 조회는 `QUICK`을 시작점으로 하되, 자료의 성격이 더 중요하면 등급을 조정한다. 세부 검증은 `execution-protocol.md`를 따른다.
