# 산출물 품질 검사

검사한 파일과 실행한 도구, 관찰된 출력을 기준으로 판정한다. 파일 확장자나 크기, 출처 URL의 존재만으로 정상·정확을 선언하지 않는다. 검사하지 못한 항목은 `NOT-RUN`으로 둔다.

## 1. 파일과 렌더링

| 산출물 | 확인 항목 |
|---|---|
| HWPX·DOCX·PPTX·XLSX | 적합한 문서 스킬 또는 설치된 도구로 컨테이너·필수 부분을 검사하고 다시 열어 내용·표·슬라이드·수식·레이아웃을 확인 |
| 마크다운·HTML | 원문과 렌더링 결과를 비교해 제목·강조·링크·표·코드가 의도대로 표시되는지 확인 |
| CSV·데이터 | 헤더·행·인코딩·계산식과 원자료를 대조 |
| 차트·이미지·영상·오디오 | 실제 파일을 열거나 재생하고 요청한 내용, 비율·크기, 글자·음향 오류를 확인 |

특정 OS의 `unzip` 명령이나 임의의 최소 파일 크기를 모든 호스트의 통과 조건으로 쓰지 않는다. 문서 파일 내부의 마크다운 기호가 원문 그대로 보이면 해당 문서 스킬의 스타일 기능으로 고치고 다시 렌더링한다.

## 2. 내용과 표현

사용자 요청의 각 항목이 실제 산출물에 들어 있는지 확인한다. 한국어 문장은 반복·과장·번역투를 문맥에서 판단한다. 특정 단어가 있다는 이유만으로 자동 FAIL을 내거나 의미를 바꾸는 치환을 강요하지 않는다. 원문·브랜드 용어·숫자·인용의 의미 보존을 확인한다.

## 3. 사실 근거

| 상태 | 판정 기준 |
|---|---|
| 확인 | 출처의 실제 내용, 시점, 범위가 해당 주장을 직접 뒷받침함 |
| 미확인 | 출처에 접근하지 못했거나 확인한 범위가 주장보다 좁음 |
| 충돌 | 원자료·공식 설명·실행 결과와 주장이 어긋남 |

가격·법령·일정·제품 기능처럼 바뀔 수 있는 정보는 현재 자료를 확인한다. 수치·날짜·사례·인증은 원출처를 대조한다. URL이나 문서명만 붙여 놓은 경우는 근거 확인을 마친 것이 아니다. 가상의 예시는 예시라고 표시하고 실제 성과처럼 제시하지 않는다.

## 4. 결과와 수정

검사 항목마다 `PASS`, `FAIL`, `NOT-RUN`과 근거를 기록한다. 전체 PASS는 요청 범위에 필요한 검사가 모두 실제로 통과했을 때만 쓴다. FAIL이면 파일·위치·문제·수정 방법을 적고 수정 후 같은 항목을 재검사한다. 검사 도구가 없거나 실제 앱에서 열어 보지 못했다면 그 한계를 적는다. 재시도 횟수를 채웠다는 이유로 결함이 남은 결과를 PASS로 바꾸지 않는다.

형식 검사 후 의미·도메인 판단은 `evaluation-protocol.md`에 따라 이어간다. 높은 위험의 산출물은 `execution-protocol.md`의 DEEP 근거 범위를 적용한다.
