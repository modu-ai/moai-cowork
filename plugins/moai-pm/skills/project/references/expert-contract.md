# 프로젝트 전문가·스킬 binding

반복될 작업마다 필요한 전문가만 만든다. 이름과 직함 대신 실제 업무 입력·근거·스킬·도구·완료 기준을 연결한다. 기존 도메인 workflow 스킬을 먼저 재사용한다.

## 각 전문가의 계약

| 항목 | 기록할 내용 |
|---|---|
| 역할 | 이 프로젝트에서 담당하는 업무와 경계 |
| 맥락 | 목적·독자·정본 사실·브랜드·관할/기준일·자산 경로 |
| 스킬 | 현재 노출된 `plugin:skill`, `metadata.version`, 본문 digest, 선택 이유 |
| 입력 | 필수 원문·데이터·형식·선행 단계 결과 |
| 출력 | 산출물 위치·구조·다음 단계가 읽을 형식 |
| 권한 | 읽기 범위·쓰기 소유권·대상 계정·요청에 포함된 변경 범위 |
| 워크플로우 | 선행 단계·병렬 가능 범위·합류·차단/재개 |
| 검수 | 출처·계산·전문 기준·의미 보존·실제 파일 검사 |
| 누락 정보 | 부모에게 전달할 질문과 영향 단계 |
| 완료 | 관찰한 증거·미실행 검사·잔여 작업 |

## 호스트 파일

Claude의 `.claude/agents/*.md`는 실제 지원 필드와 도구 allowlist를 사용한다. `Skill` 동적 로드는 유효하다. 지원될 때 꼭 필요한 짧은 기준만 `skills`로 사전 로드한다. 모든 업무 스킬의 본문을 넣지 않는다.

로컬 Codex의 `.codex/agents/*.toml`은 `name`, `description`, `developer_instructions`를 사용한다. 지원되는 `sandbox_mode`, `mcp_servers`, `skills.config`만 필요에 따라 지정한다. 모델·추론 설정은 사용자/호스트 설정을 유지한다. 호스팅 Work가 로컬 TOML을 자동 발견한다고 가정하지 않는다.

읽기 전용 감사자가 신규 외부 근거를 조회해야 하면 지원되는 읽기 도구를 주거나 부모에게 조회 요청을 반환하게 한다. 파일 allowlist와 실제 sandbox 격리를 구분한다. 감사 실행·기능 지원 여부를 관찰하지 못하면 독립 검수 완료라고 표시하지 않는다.

업무별 실제 검수 사례: 재무는 기간·단위·계산, 데이터는 버전·필터·출처, 법무는 원문·관할·기준일, 채용은 증빙·기준·평가 이유, 커머스는 상점·주문 상태, 교육은 학습 목표·평가, 창작은 사실/세계관 정본·연속성, 문서/디자인은 실제 열기·형식·브랜드를 확인한다. 구체적인 검수는 해당 스킬과 프로젝트의 완료 기준을 따른다.

공식 형식: [Claude Subagents](https://code.claude.com/docs/en/sub-agents), [OpenAI Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents).

`metadata.invocation-scope: workflow`인 스킬은 상위 워크플로우에서 호출할 의도를 보존한 것이다. 이 메타데이터는 앱의 명령 메뉴 숨김이나 권한 제어를 대신하지 않는다. 현재 호스트의 노출 방식은 따로 확인한다.
