# 산출물 평가

`quality-evaluator.md`의 파일·형식 검사를 거친 뒤, 사용자 요청과 실제 산출물을 대조한다. 작성자가 만족스럽다고 말한 것과 근거가 확인된 것은 구분한다. 모든 호스트에서 같은 기준을 적용한다.

## 평가 항목

| 차원 | 확인할 것 |
|---|---|
| 정확성 | 수치·날짜·규정·인용을 원출처와 대조했는가. 확인하지 못한 주장을 표시했는가 |
| 완전성 | 사용자가 요청한 항목이 실제 파일과 본문에 있는가 |
| 실용성 | 현재 도구·권한·예산으로 실행 가능한 다음 단계인가 |
| 톤 | 프로젝트 지침과 사용자 요청에 맞는가 |
| 도메인 | 업종·관할·대상 독자의 제약을 반영했는가 |

각 항목에 관찰한 근거, 결함 위치, 필요한 수정을 적는다. 특정 가중치나 S/A/B 등급만으로 합격을 선언하지 않는다. 구조 검사가 통과해도 의미와 사실이 맞는지는 별도로 확인한다. 외부 사실을 확인할 수 없다면 `미검증`으로 남기고 그 사실에 의존하는 주장을 확정하지 않는다.

평가 결과가 부족하면 영향이 큰 결함부터 수정하고, 바뀐 결과를 다시 읽거나 실행한다. 검증되지 않은 초안은 그 상태를 명시해 전달한다.

## 피드백

사용자가 수정 의견을 주면 해당 부분을 고치고 다시 대조한다. `/project evolve` 요청에서는 도움이 된 부분과 어긋난 부분을 짧게 물을 수 있다. 이미 제공한 의견을 반복해서 요구하지 않는다. 받은 피드백은 확인된 사실과 사용자 선호를 구분해 개선 기록에 반영한다.
