# 필요한 맥락을 묻는 방법

질문 수와 옵션 수는 현재 노출된 도구 스키마를 따른다. 다른 호스트의 상한을 복사하거나 매 호출의 슬롯을 채우기 위해 질문을 만들지 않는다.

ChatGPT에서도 구조화 질문 도구를 사용할 수 있다. 현재 세션에 노출된 질문 채널을 우선 사용해 필요한 맥락을 받는다. 선택지와 직접 답변을 활용하고, 건너뛰기는 해당 정보의 유예로 기록한다. 질문 화면에 여러 카드가 표시된다는 사실만으로 API의 호출당 상한이나 도구 이름을 추정하지 않는다.

## 도구 선택

| 채널 | 처리 |
|---|---|
| `AskUserQuestion` | 현재 정의의 질문·옵션·자유 입력 제약을 확인한다 |
| `request_user_input` | 현재 모드·용도·질문 상한·필수 필드·옵션 규칙을 확인한다. 노출되어 있어도 사용 조건을 확인한다 |
| `request_user_input_async` | `questions: [{title, options?: string[]}]`의 실제 정의를 확인한다. 자유 입력이 필요한 경우 지원되는 형식을 사용한다 |
| 질문 도구 없음 | 상위 호스트 지침에 따라 누락 정보·해당 단계·가능한 작업을 보고한다. 응답 없음은 승인도 거절도 아니다 |

비동기 질문 호출은 답을 기다리지 않고 반환한다. 답변에 의존하지 않는 작업은 진행하되 의존하는 단계는 사용자의 실제 응답까지 보류한다. 미리 선택된 옵션은 제출된 답이 아니다. 파일 업로드·스크린샷이 필요하면 그 요청을 지원하는 채널을 사용한다.

## 수집 순서

1. 사용자 요청·기존 지침·`.moai/context.md`·실제 프로젝트 자료를 먼저 읽는다.
2. 목적·산출물·독자·문체·현행 업무·품질·자산·제약의 8렌즈로 누락을 찾되 프로젝트에 해당하는 질문만 만든다.
3. 결과를 바꾸는 필수 정보부터 묻는다. 관련 질문은 인지 부담과 도구 상한 안에서 묶는다. 자유 서술·원문·구체적인 사실이 필요한 질문을 억지 선택지로 바꾸지 않는다.
4. 이미 받은 답은 재사용한다. 모호하거나 서로 충돌하면 영향을 받는 단계만 보류한다.
5. 충분하면 종료한다. 선택 정보는 유예할 수 있고, 유예로 목표·권한·정확성이 달라지는 경우 그 영향을 설명한다.

민감도는 기존 정보에서 명확하면 재질문하지 않는다. 판정할 수 없으면 `unknown`으로 저장하고 외부 전송을 하지 않는다. 프로젝트가 공개여도 개별 문서의 민감도를 다시 판단한다.

## 저장·재개

`.moai/config.json`의 `context.answers`에는 실제 값·출처·확정/미검증 여부를 저장한다. `context.questions`에는 안정적인 질문 ID·내용·영향 단계·`waiting/answered/deferred/not_applicable` 상태를 둔다. `.moai/context.md`에는 읽기 쉬운 사실·제약·자산·유예 사항을 요약한다. 답변을 받기 전에 사실처럼 채우거나 빈 맥락 파일로 덮어쓰지 않는다.

하위 에이전트는 사용자에게 직접 묻는다고 가정하지 않는다. 누락 정보·영향·진행 가능한 범위를 부모에게 반환하고, 부모가 중복 질문을 합쳐 묻는다. 필수 입력이 충분하거나 기존 요청이 이미 권한을 제공했으면 형식적인 승인 라운드를 추가하지 않는다.
