# 프로젝트 환경 진단

`/project doctor` 또는 같은 뜻의 자연어 요청에서 실행한다. 현재 프로젝트와 현재 호스트에서 관찰한 결과만 보고한다. 아래 항목은 검사 절차이며 통과 예시가 아니다.

## 검사 항목

| 항목 | 확인 방법 | 실패 또는 미확인 시 |
|---|---|---|
| 지침 정본 | 프로젝트 `AGENTS.md`를 열고 개요·워크플로우·필수 HARD 블록·500줄 상한 확인 | 없는 항목과 위치 보고 |
| Claude 포인터 | `CLAUDE.md` 전체가 `@AGENTS.md` 한 줄인지 확인 | 레거시 복제와 손상 포인터 구분 |
| 프로젝트 상태 | `.moai/config.json`을 파싱하고 실제 파일·설정과 대조 | 스냅샷 부재를 최신 상태로 간주하지 않음 |
| 설치 스킬 | 배포 로스터 `.claude-plugin/marketplace.json`과 현재 호스트에 노출된 스킬을 각각 확인 | 설치·노출·호출 가능을 별도 상태로 보고 |
| 스킬 체인 | `AGENTS.md`가 참조하는 각 스킬의 존재와 해당 호스트 호출 가능 여부 확인 | 끊긴 참조를 파일·위치와 함께 보고 |
| 에이전트 파일 | Claude `.claude/agents/*.md`, Codex `.codex/agents/*.toml`의 필요한 대응 파일 확인 | 생성 여부와 실제 호스트 발견 여부 구분 |
| MCP 연결 | 프로젝트의 `.mcp.json`, 호스트 설정, 현재 세션 도구 노출·호출 결과를 구분 | 선언만 있고 인증·호출이 없으면 미검증 |
| 생성물 | 실제 문서·이미지·동작을 확인한 경우만 완료 처리 | 검사하지 않은 영역을 미확인으로 남김 |

`.moai/credentials.env`의 존재나 내용을 진단 통과 조건으로 삼지 않는다. 토큰을 파일에서 읽어 출력하지 않는다. 특정 커넥터를 모든 프로젝트의 필수 항목으로 가정하지 않는다. ChatGPT 기본 이미지 생성과 Higgsfield는 사용자의 선택과 현재 호스트의 실제 능력에 따라 각각 확인한다.

## 수행 순서

1. 검사 대상 프로젝트 경로와 호스트를 밝힌다.
2. 파일 검사는 존재·내용·파싱 결과를 확인한다. `AGENTS.md`의 줄 수와 필수 구획은 실제 파일에서 센다.
3. 플러그인 목록은 배포 로스터와 현재 설치·노출 상태를 대조한다. `~/.claude/plugins/`만을 양쪽 호스트의 공통 설치 위치로 가정하지 않는다.
4. 필요한 MCP는 선언 → 호스트 등록 → 도구 발견 → 인증·실제 호출을 별도 단계로 확인한다.
5. 각 항목을 `PASS`, `FAIL`, `NOT-RUN`으로 표시하고 실행한 검사와 관찰 출력을 적는다. `NOT-RUN`을 `PASS`에 합산하지 않는다.
6. 수정이 필요하면 영향 파일과 조치를 제안한다. 기존 사용자 작성 구획을 자동으로 덮어쓰지 않는다.

한국어 텍스트 체인은 프로젝트 템플릿의 필수 후처리 규칙과 비교하되, 민감 문서의 외부 맞춤법 서비스 제외를 반영한다. 문서의 체인이 올바르다는 것과 실제 후처리 실행은 다른 증거다.

## 상태 조회와 보고서

간단한 상태 요청에는 검사한 항목만 요약한다. 상세 보고서를 요청하면 검사 경로, 호스트, 결과, 명령 또는 도구 출력, 미확인 사항, 조치 순서를 포함한다. `/project doctor --report` 같은 추가 플래그가 호스트에 노출되지 않으면 자연어 요청으로 보고서 파일을 만든다. 파일을 생성했다면 다시 열어 내용과 경로를 확인한다.

전체 상태를 `HEALTHY`라고 표시하려면 요청 범위의 필수 검사가 실제로 모두 통과해야 한다. 임의 가중 점수나 커넥터 키 비율로 건강 상태를 추정하지 않는다.
