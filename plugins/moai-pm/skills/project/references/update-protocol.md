# 플러그인 업데이트 동기화

`/project update` 또는 같은 뜻의 자연어 요청에서 프로젝트 지침·체인을 현재 설치 상태와 대조한다. 사용자 작성 내용을 보존하고 Claude Cowork·ChatGPT Work 양쪽의 호출 가능 상태를 확인한다. `CLAUDE.md`는 지침 정본을 가져오는 한 줄 포인터다.

## 시작 조건

- 대상 프로젝트의 `AGENTS.md`, `CLAUDE.md`, `.moai/config.json`을 읽는다. 최초 설정이 없다면 업데이트가 아닌 새 프로젝트 설정으로 안내한다.
- 기존 파일을 바로 덮어쓰지 않는다. 사용자 작성 구획과 생성 구획을 표시하고, 변경 전 내용을 복구 가능한 형태로 남긴다.
- `.moai/config.json`에 이전 인벤토리 스냅샷이 없으면 현재 상태를 기준선으로 저장할 수 있지만, **변경이 없었다거나 이미 최신이라고 주장하지 않는다**. 템플릿과 기존 지침의 차이는 별도로 검사한다.
- 추가 요청과 누적된 교정·체인 실패 신호가 있으면 읽되, 없는 신호 파일을 실제 세션 분석의 증거처럼 쓰지 않는다.

## 현재 인벤토리

1. 배포 로스터 정본 `.claude-plugin/marketplace.json`에서 플러그인 목록을 읽는다.
2. 현재 호스트에 설치·노출된 각 플러그인의 매니페스트, `skills/*/SKILL.md`, 참조 파일, `.mcp.json`, 에이전트 파일을 조사한다. 설치 경로는 호스트별로 확인하며 `~/.claude/plugins/`만을 공통 위치로 가정하지 않는다.
3. 파일 존재, 스킬 발견, 실제 호출 가능을 별개로 기록한다. MCP도 선언, 도구 발견, 인증·호출 상태를 구분한다.
4. 이전 스냅샷과 이름·버전·설명·내용 식별자를 비교해 추가·변경·제거를 나눈다. 한 호스트에만 보이는 스킬을 양쪽에서 사용할 수 있다고 표시하지 않는다.

스킬 변화가 없어도 템플릿 변화는 검사한다. `references/templates/AGENTS.md.tmpl`의 HARD 블록과 프로젝트 문서의 기존·새 값을 비교한다. 두 축이 모두 확인되기 전에는 최신 상태라고 결론 내리지 않는다.

## 변경 계획과 소유권

| 구획 | 처리 |
|---|---|
| 템플릿 소유 HARD 블록 | 이전 템플릿과 사용자 문서, 새 템플릿의 세 값을 비교 |
| 프로젝트 개요·체인·라우팅 | 사용자 목적을 보존하면서 끊긴 참조와 새 후보를 최소 범위로 갱신 |
| Claude 에이전트 | `.claude/agents/*.md`에서 해당 체인을 갱신 |
| Codex 에이전트 | `.codex/agents/*.toml`의 대응 체인을 함께 갱신 |
| `CLAUDE.md` | 파일 전체가 `@AGENTS.md` 한 줄인지 확인. 레거시 복제는 `agentsmd-generator.md`의 이관 절차 적용 |

이전 템플릿과 프로젝트 문서가 같고 새 템플릿만 바뀌었다면 해당 블록을 갱신한다. 프로젝트 문서가 사용자가 수정한 내용이고 새 템플릿도 바뀌었다면 차이를 보여주고 충돌하는 의도를 확인한다. 이전 템플릿을 구할 수 없다면 사용자 수정 가능성을 우선한다. 근거 없이 사용자 문단을 삭제하거나 통째로 재생성하지 않는다.

새 스킬이 기존 체인에 유용한지 설명을 읽고 판단한다. 제거된 스킬을 참조하는 체인은 실행 가능 대안을 찾되, 사용자 목적이 달라지는 대체는 확인한다. 삭제 예정 파일·구획은 먼저 목록과 영향 범위를 보여준다.

## 적용과 검증

1. 변경할 파일과 각 변경 이유를 요약한다. 기존 사용자 지시가 이미 업데이트를 승인했다면 같은 내용의 승인을 반복 요청하지 않는다.
2. 원문을 보존하고 필요한 파일만 수정한다. 템플릿 변수는 실제 프로젝트 정보로 치환한다. 치환되지 않은 `{변수}`가 남으면 적용을 중단한다.
3. `AGENTS.md`의 500줄 상한과 필수 HARD 블록, `CLAUDE.md` 한 줄 포인터를 검사한다.
4. 양쪽 에이전트 파일의 구문과 스킬 참조를 검사하고, 실제 호스트 발견·호출은 가능한 환경에서 별도로 확인한다.
5. MCP 설정은 JSON 구조와 크로스 플랫폼 런처를 확인한다. 도구 발견·OAuth·실제 호출은 확인한 범위만 보고한다.
6. 변경된 결과를 다시 읽고 이전 인벤토리와 새 인벤토리의 차이가 프로젝트 지침에 반영됐는지 확인한다. 통과한 검사와 미실행 검사를 분리해 기록한다.
7. 검증이 끝난 뒤에만 `.moai/config.json` 스냅샷과 `.moai/evolution/log.md`를 새 기준선으로 갱신한다.

동일한 drift 신호가 다음 세션에 없다는 사실만으로 성공을 증명하지 않는다. 검증이 실패하면 보존한 원문으로 해당 변경을 되돌리고 실제 상태를 확인한다. 여러 파일에 걸친 변경을 임의의 파일 수 제한 때문에 절반만 적용한 채 완료로 표시하지 않는다.

## 보고

추가·변경·제거된 스킬과 연결 상태, 수정한 지침·에이전트 파일, 템플릿 충돌, 실행한 검사와 출력, 확인하지 못한 호스트·MCP 기능을 보고한다. `AGENTS.md`와 에이전트 파일의 구조 확인은 데스크톱에서의 실제 스킬 실행을 대신하지 않는다.
