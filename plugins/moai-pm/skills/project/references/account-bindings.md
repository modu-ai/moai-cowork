# 프로젝트의 서비스 계정 연결

워크플로우는 비밀값 대신 서비스·대상 계정의 `account_ref`, 실제 확인한 계정·권한 범위·인증 출처를 기록한다. 실행 전에 읽기 도구로 대상 사이트·몰·사용자 식별자를 확인하고 사용자 요청의 대상과 대조한다. 변경 대상이 불명확하면 그 단계만 대기한다.

자체 MCP의 공통 자격증명 코어는 `<SERVICE>_CREDENTIALS_FILE`로 프로젝트 계정 파일을 선택한다. 예: `SMARTSTORE_CREDENTIALS_FILE`, `IMWEB_CREDENTIALS_FILE`, `CAFE24_CREDENTIALS_FILE`, `THREADS_CREDENTIALS_FILE`, `OPENAI_CREDENTIALS_FILE`. 명시적 파일 경로가 우선이고, 서비스가 별도 경로 변수 이름을 지정한 경우에는 그 이름을 따른다. 지정이 없으면 기존 `~/.moai/mcp/<service>.json` 경로를 유지한다.

실제 키·토큰 환경변수는 계정 파일보다 우선한다. 공유 환경에 다른 계정의 값이 남지 않았는지 값 자체를 출력하지 않고 설정 출처와 계정 식별자로 확인한다. 프로젝트별 OAuth 회전 파일도 `IMWEB_TOKEN_FILE`·`CAFE24_TOKEN_FILE`로 별도 지정한다. 파일의 경로는 실행하는 컴퓨터 기준이며, 호스팅 Work가 사용자의 로컬 파일을 자동으로 읽는다고 가정하지 않는다.

호스트가 MCP 프로세스별 환경 설정을 지원하는지 확인한 뒤 경로만 연결하고 프로세스를 재시작한다. 인증 파일은 제한된 개인 위치에 보관하고 버전 관리·지침·답변·로그에 넣지 않는다. 외부 연결 인증과 업무별 변경 권한은 별개이며 `ToolAnnotations`도 인증 또는 승인을 대신하지 않는다.

## 큰 도구 스키마

공식 SDK의 `list_tools()`로 입력 스키마 크기와 읽기/쓰기 혼합 여부를 측정한다. 프로젝트가 실제 노출한 도구 범위·선택 지연·잘못 선택한 action·허용되지 않은 변경을 대표 사례로 기록한다. 호스트의 도구 검색·지연 로딩이 있는지도 확인한다. 측정 없이 기존 action을 분리하면 이름·호출 호환성만 바뀔 수 있으므로, 분할은 측정한 오류 또는 호스트 한도에 대응하는 별도 버전 변경으로 처리한다.

측정 명령: 각 서버 환경에서 `python <저장소>/scripts/check-mcp-annotations.py --server <서버명>`. 이 검사는 도구 목록만 읽으며 외부 서비스 작업을 실행하지 않는다. 실제 계정 조회·변경은 따로 기록한다.
