# 이력서 직무 근거 검토

이 스킬은 직무기술서와 지원자가 제공한 경력·자격·작업 사례를 대조하는 **검토 초안**을 만듭니다. 자동 합격·거절, 지원자 간 순위, 숫자 점수나 합격 가능성 예측은 출력하지 않습니다. 채용 담당자는 원본과 근거를 직접 확인한 뒤 결정합니다.

## 1. 평가 기준 확인

- 사용자에게 직무기술서와 이력서를 받습니다. 직무기술서가 없으면 먼저 업무와 필수 요건을 정의하도록 안내합니다.
- NCS 능력단위는 해당 직무의 실제 분류를 [NCS 공식 검색](https://ncs.go.kr/unity/th03/ncsSearchMain.do)에서 확인한 경우에만 적용합니다. 분류를 찾지 못하면 임의 NCS 명칭을 만들지 않습니다.
- 여러 지원자를 비교할 경우 같은 직무 기준을 사전에 확정하고, 지원자마다 같은 항목을 적용합니다.

## 2. 개인정보와 편향 점검

- 사진, 생년월일·나이, 출신지, 가족관계, 혼인·자녀, 신체정보, 종교, 정치 성향처럼 직무 관련성이 확인되지 않은 정보는 평가에 사용하지 않고 답변에 되풀이하지 않습니다. 이름과 연락처도 결과에 불필요하면 제외합니다.
- 졸업 연도·주소·SNS처럼 나이 또는 출신지를 추정할 수 있는 간접 단서도 점수나 판단에 사용하지 않습니다.
- 원본 PDF에 사진이나 숨은 텍스트가 있으면 자동으로 완벽히 가렸다고 주장하지 않습니다. 확인 가능한 텍스트만 검토하고, 민감 정보가 남아 있으면 사용자에게 익명화된 자료를 요청합니다.
- 직무기술서에 나이·성별·혼인 여부 등의 차별적 조건이 있으면 검토를 중단하고 직무 관련 기준으로 고치도록 안내합니다.

## 3. 직무 근거 정리

| 직무 요건 | 이력서에서 확인한 근거 | 확인할 부분 |
|---|---|---|
| [실제 JD의 요건] | [민감 정보를 제외한 짧은 인용·위치] | [경험 범위나 성과의 확인 질문] |

- 이력서에 언급되지 않은 능력은 `자료에서 확인되지 않음`으로 표시합니다. 능력이 없다고 단정하지 않습니다.
- 인용은 해당 경력의 문맥을 함께 확인하고, 자기보고 성과는 검증 전 주장으로 표시합니다.
- 면접 질문은 해당 직무 요건과 자료의 공백에 맞춰 작성합니다. 질문 수는 실제 확인할 항목 수에 따릅니다.

## 4. 출력과 보관

```markdown
> 직무 근거 검토 초안입니다. 채용 담당자가 원본과 사실관계를 직접 확인하고 결정합니다.

## 적용한 직무 기준
- [직무기술서의 버전·확인한 NCS 분류 또는 일반 직무 요건]

## 근거와 확인할 항목
| 직무 요건 | 확인한 근거 | 추가 확인 |
|---|---|---|

## 면접 질문 초안
- [직무 관련 질문]

## 검토 범위와 자료 공백
- [읽은 자료, 읽지 못한 부분, 개인정보 처리 한계]
```

- 평가 시각·원본 해시·검토자·기준 문서 ID는 실제 도구로 확인하거나 사용자가 제공한 경우에만 기록합니다. 저장하지 않았는데 감사 로그를 만들었다고 표시하지 않습니다.
- 보관 기간은 일률적인 `4년`으로 정하지 않습니다. 실제 채용 지역의 법령, 서류 반환·파기 의무, 회사의 보존 정책을 확인합니다. 한국에서는 [채용절차법 원문](https://www.law.go.kr/lsInfoP.do?lsiSeq=208371)의 적용 범위와 서류 반환 조항을 확인합니다.
- 국외 채용이면 관할별 규정을 별도로 확인합니다. 사람의 최종 검토만으로 자동화 채용 도구의 규제가 면제되는 것은 아닙니다. 예를 들어 [뉴욕시 공식 안내](https://home4.nyc.gov/site/dca/about/automated-employment-decision-tools.page)는 적용 대상 AEDT 사용에 편향 감사·결과 공개·고지를 요구합니다. [미국 EEOC의 AI·ADA 안내](https://www.eeoc.gov/eeoc-disability-related-resources/artificial-intelligence-and-ada)도 함께 확인합니다.

## 사용 범위

- 직무기술서·면접 절차 설계는 `moai-recruiter:hr-employment`를 사용합니다.
- 실제 채용 결정, ATS 상태 변경, 지원자에게 합격·거절 통지는 담당자의 별도 승인과 해당 시스템 접근이 필요합니다.
