# 채용 파이프라인 (90-hiring-pipeline)

> MoAI-Cowork v1.0.0 하네스 참고 자료

## 개요
채용 프로세스(공고 작성→소싱→스크리닝→면접→평가→오퍼)를 역할별로 설계하는 참고 절차입니다. 현재 앱에서 여러 작업자를 지원하면 분담하고, 그렇지 않으면 한 대화에서 순서대로 수행합니다.

## 전문가 역할

- **면접 설계자**: 면접 구조 설계, 역량 기반 질문, 면접관 가이드, 평가 양식 설계 전문가
  - 면접 단계별 시간, 면접관 구성 설계
  - STAR 기법 기반 행동 면접 질문 설계
  - 직무별 기술 역량 평가 방식 설계
  - 면접관 교육 자료 및 진행 가이드 작성
  - 구조화된 평가 양식 설계

- **공고 작성자**: 직무 분석, 역량 정의, 직무 기술서(JD), 채용 공고 작성 전문가
  - 핵심 책임, 기대 성과, 보고 관계 정의
  - 필수(Must-have) 및 우대(Nice-to-have) 역량 구분
  - 정식 공고 작성
  - 외부 채용 공고 작성
  - 평가 및 면접 기준이 되는 역량 기준 수립

- **오퍼 조정자**: 최종 평가 보고서, 오퍼 패키지 설계, 오퍼 작성, 온보딩 담당
  - 전체 단계 평가 결과 통합 분석
  - 등급별, 인원별 혜택 포함 패키지 설계
  - 정식 채용 제안서 작성
  - 등급/조건 협상 전략 수립
  - 파이프라인 일관성 검증

- **스크리닝 전문가**: 평가 기준 정의, 과제 설계, 스크리닝 가이드 작성
  - 역량별 포트폴리오 평가 설계
  - 직무 관련 과제 또는 테스트 설계
  - 면접 질문 및 평가 기준 설계
  - 후보자 비교 스코어카드 설계
  - 단계별 시간 기준 설정

- **소싱 전문가**: 채용 채널 전략, 탐색 시스템 구축, 메시지 설계
  - 직무별 양질의 소싱 채널 선정
  - 후보자 검색 및 부울 검색 전략 설계
  - 후보자 접근 메시지/이메일 템플릿 작성
  - 회사/팀 역량 홍보 콘텐츠 설계
  - 채널별 반응, 비용, 기간 추적 지표 설정

## 워크플로우

1. 실제 직무와 팀의 업무, 고용 형태, 근무 조건을 확인합니다. 급여나 채용 기한은 사용자 자료가 없으면 채우지 않습니다.
2. 직무기술서와 직무 관련 평가 항목을 먼저 정합니다. 보호 특성·간접 단서를 평가 기준에 넣지 않습니다.
3. 소싱·면접·온보딩 계획은 요청한 범위만 작성합니다. 후보자의 개인정보를 임의 파일로 복사하지 않습니다.
4. 지원서 검토는 `hr-resume-screener`의 근거 정리 계약을 따르고, 채용 결정·오퍼 조건은 담당자가 직접 승인합니다.
5. 사용자가 파일을 요청했고 현재 앱에서 저장할 수 있을 때만 지정된 경로에 기록합니다. 산출물마다 근거와 미확인 조건을 표시합니다.

## 오류 처리

| 오류 유형 | 대응 전략 |
|----------|----------|
| 직무 정보 부족 | 공고 작성자가 템플릿 및 가이드 제공 |
| 예산 정보 없음 | 급여 범위와 오퍼 조건을 비워 두고 사용자에게 확인할 항목 제시 |
| 검색 실패 | 일반적인 JD/소싱 전략 기반, "[시장 데이터 미반영]" 표시 |
| 도구 사용 불가 | 현재 앱의 기능으로 가능한 범위만 수행하고 누락 범위를 표시 |
| 일관성 문제 | 오퍼 조정자 수정 요청 → 재작업 (최대 2회) |
