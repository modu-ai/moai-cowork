# 채용공고 분석기 (hr-job-analysis)

채용공고에 적힌 요건과 공개 기업 자료를 분리해 검토합니다. 채용 의도·합격 가능성·이직률은 공고 문구나 채용 빈도만으로 단정하지 않습니다.

## 지원 영역

| 영역 | 설명 |
|------|------|
| JD 분석 | 채용공고에서 필수/우대 역량 추출, 키워드 매핑 |
| 경험 매칭 | 내 경험과 JD 역량 매칭 → 자소서 소재 발굴 |
| 기업 분석 | 기업 문화, 최근 동향, 성장성, 경쟁사 비교 |
| 전략 수립 | 지원 전략 로드맵, 약점 보완 계획 |

참조 가이드: `references/jd-analysis-guide.md`

## 분석 기준

1. 공고의 원문 URL·게시일·마감일과 채용 회사·직무를 확인합니다. 공고를 읽지 못했다면 해당 직무의 일반 정보를 실제 공고 분석처럼 제시하지 않습니다.
2. 필수·우대 요건을 그대로 추출하고, 표현이 모호하면 채용 담당자에게 확인할 질문으로 남깁니다. 임의 키워드 점수나 70% 합격 기준을 만들지 않습니다.
3. 사용자가 자기 경험을 제공했을 때만 요건별 근거를 연결합니다. 언급되지 않은 경험을 결여로 단정하지 않습니다.
4. 기업 재무는 공개 공시가 있는 경우에만 [DART](https://dart.fss.or.kr/) 등의 원문에서 기준 연도와 연결 기준을 확인합니다. 공시가 없으면 재무 건전성을 판단하지 않습니다.
5. 직원 후기·채용공고 반복·홍보 자료는 제한된 관찰입니다. 이직률·조직 문화·채용 시급성의 확정 근거로 쓰지 않습니다.

## JD 분석 프레임워크

### 1단계: 구조 분해

채용공고를 다음 요소로 분해합니다.

```
[직무 개요]     → 핵심 역할과 포지션 레벨 파악
[담당 업무]     → 일상 업무 vs 프로젝트성 업무 구분
[필수 자격]     → 공고에 명시된 요건과 예외 조건 확인
[우대 사항]     → NICE-TO-HAVE: 있으면 차별화
[근무 조건]     → 계약 형태, 위치, 보상 구조
[기업 문화]     → 공식 안내와 후기의 차이를 구분하고 면접에서 확인
```

### 2단계: 역량 추출 및 분류

| 분류 | 예시 | 가중치 |
|------|------|--------|
| 하드 스킬 | Python, SQL, Figma, 재무 분석 | 높음 |
| 소프트 스킬 | 커뮤니케이션, 리더십, 문제해결 | 중간 |
| 도메인 지식 | 핀테크, 이커머스, 헬스케어 | 높음 |
| 자격/인증 | SQLD, CPA, 정보처리기사 | 조건별 |

### 3단계: 경험 매칭 매트릭스

```
역량 항목    | JD 요구 수준 | 내 보유 수준 | 갭  | 자소서 소재
─────────────┼─────────────┼─────────────┼─────┼──────────────
Python       | 상           | 중           | ▲   | 프로젝트 X 경험
데이터 분석   | 중           | 상           | ◎   | 인턴 성과 강조
팀 리더십     | 중           | 중           | ─   | 동아리 회장 경험
```

- ◎ 강점: 자소서에서 적극 어필
- ─ 충족: 간결하게 언급
- ▲ 갭: 학습 의지와 보완 계획 제시

## 기업 분석 체크리스트

| 항목 | 확인 내용 | 소스 |
|------|----------|------|
| 사업 모델 | 주요 매출원, B2B/B2C, 핵심 제품 | 사업보고서, IR 자료 |
| 재무 건전성 | 매출 추이, 영업이익률, 투자 라운드 | 전자공시(DART), 뉴스 |
| 조직 문화 | 수평/수직, 원격근무, 복지 | 잡플래닛, 블라인드, 채용 페이지 |
| 최근 동향 | 신사업, 인수합병, 리더십 변화 | 뉴스, 보도자료 |
| 경쟁 환경 | 주요 경쟁사, 시장 점유율, 차별화 | 산업 보고서 |
| 채용 패턴 | 공채/수시, 채용 주기, 선호 인재상 | 과거 공고, 채용 후기 |

## 헤드헌터 제안 검토

- 제안서를 실제로 받았다면 직무, 고용 주체, 보상 구성, 근무지, 보고 관계, 계약 조건과 공식 채용공고의 일치 여부를 확인합니다.
- 급여 수준·재무 상태는 현재 공개 자료가 있는 경우에만 비교합니다. 특정 영업이익률·부채비율을 일률적 위험 기준으로 쓰지 않습니다.
- 평판 사이트의 후기는 작성자와 사실관계를 확인하기 어려우므로 개인 의견으로 표시합니다.
- 제안만으로 채용 가능성이나 헤드헌터의 신뢰도를 숫자로 평가하지 않습니다.

## 독립 실행 워크플로우

참조 가이드(`references/`)를 사용할 수 없는 경우 다음 단계로 실행합니다.

### 1단계: 입력 확인
- 채용공고 텍스트 또는 기업명/직무명 확인
- 사용자 배경 정보 수집 (있는 경우)

### 2단계: JD 구조 분해
- 필수/우대 역량 추출
- 하드 스킬/소프트 스킬/도메인 지식 분류

### 3단계: 기업 리서치 (요청 시)
- 기업 개요, 사업 모델, 재무 상태 정리
- 조직 문화, 최근 뉴스, 채용 패턴 분석

### 4단계: 매칭 및 전략
- 사용자 경험과 JD 역량 매칭
- 강점 어필 포인트 + 갭 보완 전략 제시
- 자소서 소재 추천

## 실행 규칙

1. 사용자 요청 수신 → JD 분석 또는 기업 분석 판별
2. `references/{id}.md` 존재 시 로드 → 가이드에 따라 실행
3. 복잡한 다기업 비교는 현재 앱에서 접근 가능한 원문 자료를 각 기업별로 확인하고 같은 기준으로 대조
4. 분석 결과를 표 형태로 정리하여 제시

## 문제 해결

- **채용공고 텍스트 없음**: 기업명과 직무명만 있어도 일반적인 해당 직무 역량 분석이 가능합니다. 정확한 분석을 위해 공고 원문을 붙여넣어 주세요.
- **비공개 기업 정보**: 스타트업이나 중소기업은 공개 정보가 제한적일 수 있습니다. 로켓펀치, 크런치베이스 등을 병행 확인하세요.
- **다수 기업 비교**: 3개 이상 기업을 비교할 때는 비교 기준(연봉, 성장성, 문화 등)을 먼저 정해주세요.
- **오래된 채용공고**: 채용 시장 트렌드는 빠르게 변합니다. 3개월 이상 된 공고는 최신 정보와 다를 수 있습니다.

## 이 스킬을 사용하지 말아야 할 때

- **자소서/이력서 작성**: JD 분석 결과를 바탕으로 문서를 작성하려면 `moai-career:career-resume` 스킬을 사용하세요.
- **면접 준비**: 분석된 역량 기반으로 면접을 준비하려면 `moai-career:career-interview` 스킬이 적합합니다.
- **포트폴리오 구성**: 프로젝트 정리는 `moai-career:career-portfolio` 스킬을 사용하세요.
- **시장조사/경쟁 분석**: 투자 목적의 기업 분석은 `moai-consultant:consult-market` 스킬이 적합합니다.

본 스킬이 산출하는 한국어 텍스트는 배포 전 의무 게이트를 통과합니다:

1. `moai-coworker:ai-slop-reviewer` — 1차 일반 AI 슬롭 검수 (금지어, 구조 패턴, 리듬)

두 게이트는 대시 대비 헤드라인·조사·체언 종결 조각문·"A에서 B로" 전환 공식 S1 패턴을 잡아냅니다. 게이트 통과 없이 산출물을 바로 배포하지 않습니다.
