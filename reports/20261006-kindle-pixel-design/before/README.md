# MoAI-Cowork e-ink 디자인 시안

현재 적용 중인 DS v2와 구분한 **검토용 제안**이다. 사용자가 시안을 선택하기 전에는 기존 사이트·본문·인포그래픽을 일괄 변경하지 않는다.

## 시안 열기

```bash
python3 -m http.server 1314 --bind 127.0.0.1 --directory www/design-system/eink-proposal
```

- A · 종이책: `http://127.0.0.1:1314/?style=paper#home`
- B · 전자책: `http://127.0.0.1:1314/?style=reader#home`
- 수업: `#lesson` / 도식: `#diagrams` / 구성 요소: `#components`

시안 안의 수업 목차와 실제 화면 안내 링크는 기존 문서 로컬 서버(1313)를 새 탭으로 연다. 시안의 홈·수업·도식·구성 요소 전환은 1314 안에서 동작한다. 사용자 입력은 외부로 전송하지 않는다.

## 기준 파일

| 파일 | 역할 |
|---|---|
| `tokens.json` | 무채색, 글꼴, 간격, 형태, 두 스타일의 기준 |
| `prototype.css` | 문서 셸과 구성 요소 구현 |
| `prototype.js` | 스타일·화면 전환, 키보드 탭, 요청 복사, 입력 확인 |
| `prototype.template.html` | 입문자용 화면과 실제 본문 예시 |
| `mermaid.config.json` | Mermaid의 색·글꼴·간격 설정 |
| `diagrams/*.mmd` | 도식 5개의 편집 가능한 원본 |
| `rendered-diagrams.json` | 실제 브라우저에서 렌더링한 SVG |
| `render-provenance.json` | 렌더링한 원본·설정·번들의 해시 |
| `build.py` | 원본·설정을 검증하고 단일 HTML 시안 생성 |
| `index.html` | 비교용 완성 시안. CSS·JS·SVG를 내장 |

## 두 스타일의 차이

| 항목 | A · 종이책 | B · 전자책 |
|---|---|---|
| 바탕 | 연회색 `#f7f7f7` | 흰색 `#ffffff` |
| 큰 제목 | 시스템 명조 | 시스템 고딕 |
| 본문 | 시스템 고딕 18px, 행간 1.85 | 동일 |
| 본문 최대 폭 | 740px | 800px |
| 절 사이 간격 | 64px | 48px |
| 문서 목차 | 넉넉한 간격 | 더 조밀한 간격 |
| 선·면·상태·도식 | 동일한 무채색 기준 | 동일한 무채색 기준 |

설치된 시스템 글꼴에 따라 형태와 폭이 달라질 수 있다. 특정 폰트를 웹에서 불러오지 않는 시안이다. 실제 e-ink 기기의 잔상·새로고침 성능을 재현하거나 검증한 결과는 아니다.

## 구성 요소 규칙

| 구성 요소 | 규칙과 동작 |
|---|---|
| 헤더·탐색 | 이름과 위치를 글자로 표시. 선택은 밑줄. 작은 화면에서는 줄바꿈 |
| 수업 목차 | 번호·제목·현재 수업. 실제 수업 링크 유지 |
| 본문·제목 | 본문 18px, 보조 설명 14px 이상. 긴 한글은 영역에 맞춰 줄바꿈 |
| 버튼 | 기본·먹색 강조·비활성. 일반 버튼 높이 44px, 비교용 작은 버튼 36px |
| 포커스 | 먹색 2px 외곽선. 그림자·애니메이션 없이 표시 |
| 상태 | 이름을 항상 표시. 완료는 먹색 면, 검토 전은 파선, 미확인은 점선 |
| 비교 표 | HTML `table`, 열·행 제목과 설명. 좁은 화면에서는 표 영역 안에서 이동 |
| 요청 블록 | 복사 가능한 텍스트. 자동 줄바꿈. 복사 성공·실패 표시 |
| 탭 | 선택 밑줄, ARIA 연결. 좌우 화살표·Home·End로 선택 |
| 접기·확인 문제 | 기본 `details`와 `summary`. 내용을 숨기더라도 펼쳐 읽을 수 있음 |
| 질문·입력 | 명시적 label, 선택·확인. 외부 전송 없는 로컬 시안 동작 |
| 안내 | 왼쪽 먹색 선과 제목. 색·아이콘에만 의존하지 않음 |
| Mermaid | 짧은 노드 이름과 연결 관계. 설명은 본문에 둠 |
| 수치 차트 | 실제 수치·눈금·원자료 표. 면·해칭·라벨로 구분 |
| 실제 앱 화면 | 원본 캡처를 보존. 앱 화면을 임의로 다시 칠하지 않음 |
| 이전·다음 | 수업 흐름을 이어 주는 글자 링크 |

요청받은 불필요한 머리말과 푸터를 시안에 넣지 않는다. 그림이라는 이유만으로 별도 설명 절을 반복 생성하지 않는다.

## 어떤 내용을 그림으로 만들 것인가

- 짧은 정의, 항목 비교, 상태, 단순 순서, 실습 요청: HTML 본문·표·목록으로 통합한다.
- 의존 관계, 분기·합류, 담당자 간 인계, 되돌아가는 과정: Mermaid로 표현한다.
- 분모·비율·변화처럼 수치를 비교해야 하는 내용: 차트와 원자료 표를 함께 제공한다.
- 공간 배치나 실제 사물 설명이 필요한 경우에만 별도의 일러스트를 검토한다. 텍스트 카드 이미지를 자동으로 늘리지 않는다.
- 실제 조작 위치: 앱을 구동해 촬영한 화면을 쓴다. 그림으로 가짜 UI를 만들지 않는다.

## 한글 폭과 도식 접근성

렌더링과 표시 단계의 글꼴을 일치시킨다. 전역 `fontFamily`와 `htmlLabels: false`를 설정하고, 노드 안쪽 여백은 16px로 둔다. 한글 라벨을 SVG 텍스트로 렌더링해 `foreignObject` 영역의 잘림을 피한다.

SVG를 다른 화면에 넣을 때 CSS로 글꼴만 바꾸면 측정 폭이 달라질 수 있다. **글꼴·크기·본문을 바꾸면 도식도 다시 렌더링한다.** 원본 해시가 달라졌는데 오래된 SVG로 빌드하려 하면 `build.py`가 중단한다.

최종 시안은 도식의 원래 크기를 유지하며, 작은 화면에서는 도식 영역 안에서 가로로 이동한다. 페이지 전체가 옆으로 넘치지 않게 한다. 수업의 주요 도식에는 같은 순서를 글로 읽는 접기 설명도 제공한다. 모든 Mermaid 원본에 `accTitle`과 `accDescr`을 넣는다.

공식 기준: [Mermaid 설정](https://mermaid.js.org/config/schema-docs/config.html), [테마 설정](https://mermaid.js.org/config/theming.html), [접근성](https://mermaid.js.org/config/accessibility.html). 공식 문서의 설정을 참고하고, 실제 저장소 번들에서 렌더링이 되는지 별도로 확인했다.

## 다시 만들기

본문·CSS·JS만 수정했을 때:

```bash
python3 www/design-system/eink-proposal/build.py
```

Mermaid 원본이나 설정을 수정했을 때:

1. `python3 www/design-system/eink-proposal/build.py --prepare-render` 실행.
2. 로컬 `_render.html`을 실제 브라우저에서 열어 5개 도식의 결과 확인.
3. SVG DOM과 원본·설정 해시를 각각 `rendered-diagrams.json`, `render-provenance.json`에 저장.
4. `build.py` 실행. 시안의 한글 라벨 경계·모바일 폭·대비 확인.

`_render.html`과 `js` 심볼릭 링크는 로컬 렌더링 준비용이다. 완성 시안에는 Mermaid 실행 스크립트가 필요하지 않다. 렌더링용 로컬 서버를 외부 공개용 서버로 사용하지 않는다.

## 선택 후 일괄 적용 순서

1. 선택된 토큰과 글꼴을 정식 디자인 기준에 반영한다.
2. 공통 사이트 셸·스타일·Mermaid 설정을 반영하고 렌더링 뒤 색을 치환하는 기존 경로를 교체한다.
3. 전수 계획의 HTML 통합 대상은 기존 표·목록을 정리하고 중복 그림을 제거한다.
4. Mermaid 대상과 실제 수치 차트를 각 본문의 근거에 맞춰 제작한다. 현재 본문에서 쓰는 PNG 4개는 새 도식으로 교체한다.
5. 출시 기록의 Mermaid 27개는 당시 내용을 유지하면서 표시 스타일만 통일한다. 현재 사용하지 않는 PNG 13개는 삭제하지 않고 보관한다.
6. PC·태블릿·모바일에서 글자와 도식 경계, 복사·탐색·질문 UI, 링크와 자료를 검사한다.
7. 기존 공개 사이트와의 배포 여부를 별도로 기록한다.
