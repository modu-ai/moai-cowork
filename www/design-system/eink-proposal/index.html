예제 · 고객 문의 6건결과 · FAQ와 안내문 초안

이번 수업에서 배울 내용

  • 각 담당자의 입력과 결과를 정합니다.
  • 함께 진행할 수 있는 작업을 찾습니다.
  • 원문과 정책을 기준으로 두 결과를 검토합니다.

어떤 일이 동시에 가능할까요?

문의 분석이 끝나면 FAQ와 안내문은 같은 유형 표와 정책을 받아 각각 작성할 수 있습니다. 검토 담당자는 두 초안이 준비된 뒤에 시작합니다.

순서를 글로 읽기

목표와 자료 확인 → 문의 분석 → FAQ와 안내문을 각각 작성 → 두 결과 합치기 → 원문·정책으로 검토 → 사용자 확인. 수정이 필요하면 작성 단계로 돌아갑니다.

같은 파일을 동시에 고치지 않습니다.

FAQ 초안과 안내문 초안을 별도 파일로 만들고, 합칠 담당자와 기준을 정합니다. 별도 에이전트 실행을 지원하지 않는 환경에서는 같은 역할로 순서대로 진행합니다.

담당자에게 무엇을 넘길까요?

“FAQ를 맡아 줘”라는 역할 이름만으로는 충분하지 않습니다. 받을 자료, 만들 결과, 시작할 조건을 함께 적어 주세요.

직접 요청해 보세요

가상 문의 자료로 먼저 실행해 보세요. 실제 사용할 수 있는 스킬과 에이전트 기능을 확인한 뒤, 역할에 맞는 방법을 선택하도록 요청합니다.

실습 요청

먼저 현재 사용할 수 있는 스킬과 에이전트 기능을 확인해 줘.
각 역할의 입력·출력·완료 기준을 계획에 적어 줘.
문의 분석 뒤 FAQ와 안내문을 별도 파일로 작성해 줘.
지원되는 경우 독립된 작성 작업을 병렬로 진행해 줘.

빠진 정책은 질문하고, 실제 게시나 고객 발송은 하지 마.

관계 · 분기 · 인계 · 반복

그림이 필요한 곳에,
도식을 씁니다.

픽셀 그림으로 업무가 갈라지고 다시 만나는 모습과 자료의 연결 관계를 보여 줍니다. 분기와 인계는 편집 가능한 Mermaid 예시도 함께 살펴보세요.

분기와 합류

선행 분석이 끝나야 작성 작업을 나눌 수 있고, 두 초안이 모여야 검토할 수 있습니다. 검토를 통과한 결과는 사용자에게, 수정 사항은 작성 담당자에게 전달합니다.

질문과 보류

필수 정보가 없으면 해당 작업을 보류합니다. 그 조건과 무관한 작업만 별도로 진행합니다. 답을 받기 전에는 미정 상태가 유지됩니다.

프로젝트와 폴더의 경계

앱 프로젝트에 모은 맥락과 컴퓨터의 실제 파일은 역할이 다릅니다. 점선 연결은 실행 환경이 폴더 접근·저장을 지원하고 범위를 확인했을 때 사용합니다.

담당자 사이의 인계

초안만 보내지 말고 원문·기준·근거를 함께 넘깁니다. 검토 의견은 작성 담당자에게 돌아가고, 확인된 결과와 미정 사항을 사용자에게 전달합니다.

다음 업무로 이어지는 순환

검토에서 찾은 기준을 지침에 남기면 다음 업무가 같은 출발점에서 시작됩니다.
