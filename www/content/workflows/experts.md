**분업 전에 맡길 일과 필요한 자료를 정합니다.** “전문가처럼 해 줘”보다 사용할 스킬·결과 형식·검토 기준을 지정하는 편이 업무를 확인하기 쉽습니다.


![분석 후 독립적인 작성 작업을 진행하고 합쳐서 검토하는 순서](/infographics/kindle/parallel-ko.png)

분류가 끝난 문의 표와 같은 정책을 FAQ 작성자와 안내문 작성자가 각각 받아 별도 초안을 만듭니다. 그림에서 같은 높이에 놓인 두 작성 작업만 병렬 후보입니다. 결과 파일을 나누고, 두 초안이 모인 뒤 검토를 시작합니다.

점선은 검토 의견이 작성 단계로 돌아가는 길입니다. “영업일 2일 이내 출고”가 “이틀 안에 도착”으로 바뀌었다면 작성자가 정책에 맞춰 고친 뒤 다시 검토합니다. 현재 앱이 별도 에이전트 실행을 지원하지 않으면 같은 역할과 기준으로 순서대로 수행합니다.

## 담당자마다 정할 여섯 가지

1. 역할과 목표: 시장 조사 담당, 보고서 작성 담당처럼 구체적으로 정합니다.
2. 사용할 스킬: 현재 작업에서 실제 사용할 수 있는 스킬만 배정합니다.
3. 입력: 읽을 자료와 앞 단계의 결과물을 지정합니다.
4. 출력: 파일·표·메모의 형식과 저장 위치를 지정합니다.
5. 완료 기준: 출처, 단위, 누락 항목 등 확인할 조건을 정합니다.
6. 질문과 인계: 부족한 정보는 질문하고 다음 담당자에게 넘길 내용을 남깁니다.

## 순차 진행과 병렬 진행

| 방식 | 적용할 때 | 예 |
|---|---|---|
| 순차 | 앞 결과가 다음 작업에 필요 | 자료 확인 → 수치 분석 → 보고서 |
| 병렬 | 입력과 출력이 독립적 | 서로 다른 경쟁사 조사 후 비교표로 합치기 |
| 병렬 뒤 합류 | 각 결과의 기준을 맞춰 통합 | 출처·기간·단위를 맞춘 뒤 최종 정리 |

같은 파일을 동시에 고치는 업무는 분리하거나 순서대로 실행합니다. 병렬 결과는 완료 상태와 누락을 확인한 뒤 합칩니다.

## 현재 앱에 하위 에이전트가 없다면

부모 AI가 스킬을 읽고 역할별 단계를 순차 수행할 수 있습니다. 이 경우 실제 별도 에이전트가 독립 실행됐다고 표시하지 않습니다. Claude의 Markdown 에이전트와 로컬 Codex의 TOML 설정, ChatGPT Work의 기능은 각 환경에서 따로 확인합니다.

```text
조사·작성·검토 역할을 나눠 줘. 각 역할의 스킬, 입력, 결과, 완료 기준을 알려 줘.
독립적인 조사만 병렬로 진행하고, 같은 파일은 동시에 수정하지 마.
사용자 답변이 필요한 항목은 질문으로 모아 전달해 줘.
```
