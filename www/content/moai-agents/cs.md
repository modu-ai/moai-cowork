**이 역할은 문의 분류와 FAQ 초안을 준비할 때 살펴보세요.** 먼저 고객 문의·서비스 정책을 제공합니다. 아래 기능 목록은 패키지 원본에서 생성하며, 실제 사용할 수 있는 기능은 현재 앱에서 확인합니다.


<!--more-->


## 첫 요청

```text
고객 문의를 유형별로 분류하고 정책에 근거한 FAQ 초안을 만들어 줘.
부족한 맥락은 질문하고, 사용한 자료와 아직 확인하지 못한 항목을 남겨 줘.
```

## 준비할 자료와 결과

| 준비물 | 결과 | 확인 기준 |
|---|---|---|
| 고객 문의·서비스 정책 | 문의 분류와 FAQ 초안 | 제공 자료와 일치하고 미정 항목을 구분 |

외부 연결 없이 제공 자료로 초안을 만들 수 있습니다. 실시간 조회·생성·게시가 필요할 때는 현재 도구와 연결 계정을 확인합니다. 실제 실행이 없으면 초안·제작안 단계로 표시합니다.

## 가상 예제로 더 이해하기

아래 자료와 모범 설명은 수업을 위해 작성했습니다. 실제 회사·고객의 실적이나 앱 실행 결과가 아닙니다. 먼저 제공 자료로 작은 결과를 만든 뒤 자신의 자료로 바꿔 보세요.

```text
수업용 문의 6건: 배송 3건, 반품 2건, 결제 1건. 정책은 영업일 2일 이내 출고, 고객지원 창구로 반품 신청. 배송 완료 시점·반품 비용·결제 승인 기준은 없음.
```

### 먼저 확인할 질문

현재 정책 버전과 답변 공개 범위는 무엇인가요? 반품 비용과 결제 담당 절차가 있나요? 답을 모르면 해당 항목을 미정으로 남기고, 그 정보 없이 가능한 범위를 정합니다.

### 모범 결과를 읽는 방법

유형 합계 6건을 표시하고 출고 기준과 도착 시점을 구분합니다. 반품 비용과 결제 정책은 확인 필요로 남깁니다. 원문 ID를 FAQ 근거에 연결합니다. 문장과 서식은 달라도 이 기준을 충족하는지 직접 비교합니다. 원문 위치·출처·상태가 결과에 함께 남으면 다음 검토자에게 넘기기 쉽습니다.

### 직접 비교할 모범 결과

| 항목 | 결과 예시 | 근거·상태 |
|---|---|---|
| 배송 FAQ | 영업일 2일 이내 출고 | 정책 원문·배송 문의 3건 |
| 반품 FAQ | 고객지원 창구로 신청 | 정책 원문·반품 문의 2건 |
| 미확인 정책 | 배송 도착 시점·반품 비용·결제 승인 | 정책 자료 없음 |
| 검토할 초안 | 결제 문의 1건에 대한 정책 요청 | 원문 확인 필요 |

### 흔한 실수와 수정 요청

2일 이내 출고를 2일 이내 도착으로 바꾸거나 반품이 항상 무료라고 씁니다. 이때는 결과 전체를 다시 만들어 달라는 말보다, 틀린 기준과 고칠 위치를 구체적으로 알려 주세요.

```text
출고와 도착을 구분해 줘. 반품 비용과 결제 기준은 자료에 없으니 확인 필요로 남겨 줘.
수정한 부분과 아직 확인할 항목을 따로 알려 줘.
```

### 확인 문제

정책이 빠진 유형 때문에 모든 FAQ 작성을 멈춰야 할까요?

<details><summary>답안과 해설 보기</summary>

근거가 있는 배송·반품 절차는 작성하고, 근거가 없는 비용·결제 항목만 보류해 필요한 질문을 모읍니다.

</details>

### 내 업무로 바꿔 보기

예제의 자료를 자신의 공개 가능한 자료로 바꾸고, 결과의 독자와 형식을 다시 정합니다. 변하지 않는 검토 기준은 프로젝트 지침에 저장하고, 이번 작업의 수치와 미정 조건은 새 자료로 제공합니다. [프로젝트와 자료 수업](/learn/02-project-context/)에서 구분 방법을 확인합니다.
