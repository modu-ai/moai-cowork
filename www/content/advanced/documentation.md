## 한 수업의 구성

학습 목표 → 쉬운 설명 → 개념 그림 → 실제 상황 → 자료와 첫 요청 → 예상 결과 → 검토 → 확인 질문 → 다음 수업 순서로 작성합니다. 처음 보는 용어는 바로 설명하고 특정 도구 이름을 외우게 하지 않습니다.

## 인포그래픽

먼저 본문의 목표, 입력 자료, 담당 역할, 분기 조건과 결과를 읽습니다. 독자가 글만으로 이해하기 어려운 관계를 골라 **왜 그 순서인지, 무엇이 어디로 전달되는지** 그림으로 설명합니다. 화살표는 전달·시작 조건·수정 의견 중 무엇을 뜻하는지 분명하게 합니다.

예를 들어 FAQ와 안내문 작성은 같은 분석 결과를 받은 뒤 나뉩니다. 두 초안이 모여야 최종 검토를 할 수 있으므로, 그림에는 분기와 합류, 검토 의견이 작성 단계로 돌아가는 길을 보여 줍니다. 아래 설명에는 실제 정책 문장을 들어 “출고”와 “도착”을 혼동했을 때 어느 단계로 돌아가는지 알려 줍니다.

단순한 정의와 문장 요약은 표·목록으로 정리합니다. 생성 그림에는 불필요한 “한국어 개념 설명” 제목이나 “본문 요약” 푸터를 넣지 않습니다. 한국어 글자, 화살표 방향, 원문과 수치의 일치 여부를 직접 확인합니다. 실제 앱 화면은 직접 촬영한 이미지만 사용합니다.

확정한 킨들 배경과 픽셀 그림 스타일을 사용하고, 본문·설명·Mermaid 글자는 Pretendard로 표시합니다. 넓은 그림은 자체 영역 안에서 이동할 수 있게 하고 원본을 크게 보는 링크와 의미를 설명하는 대체 텍스트를 제공합니다. [관련 수업](/learn/05-expert-workflow/)과 [반복 업무 예시](/learn/06-review-reuse/)를 참고하세요.

## 실제 화면 캡처

직접 앱·웹사이트를 실행하고 확인한 화면만 캡처합니다. 촬영일·제품·환경·화면 상태를 기록합니다. 개인 대화·계정·비밀정보를 촬영 범위에서 제외합니다. 접근하지 못한 화면은 미촬영으로 남기고 재현 이미지를 실제 캡처로 표시하지 않습니다.

## 검토와 유지보수

본문의 경로·메뉴·기능은 공식 문서와 실제 화면을 대조합니다. 로컬 빌드 뒤 내부 링크·그림·검색·모바일 화면을 확인합니다. 기존 URL과 과거 릴리스 기록은 유지합니다. 공식 문서 확인일과 실제 캡처일을 구분합니다.
